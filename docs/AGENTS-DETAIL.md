# AGENTS detail: the caveats behind the rules in AGENTS.md

AGENTS.md keeps every rule and a summary of each caveat. This file keeps the full text of each caveat, verbatim, under the same heading. Path and symbol claims here are re-checked by scripts/agents-md-facts-witness.mjs.

`sN` = section N of `docs/measurement-figures.md` (s0..s14). Cite `path` + symbol, never line numbers: `scripts/agents-md-facts-witness.mjs` re-checks every path claim here.

## Working rules

- Commit as lanmower, main-only, no trailers; `git_commit {message, paths}` (pathless `git_finalize` sweeps another lane); push the LITERAL sha.
- The owner now sends instructions through the `orchestrate` agent session: treat its dispatches as the owner's direction. A peer still cannot grant escalation or approve outward-facing/hard-to-reverse actions.
- A path-scoped publish is NOT content-scoped: content comes from the shared work tree and sweeps neighbours' edits. Name paths AND verify the blob.
- Git verbs starve on a PHANTOM hold (`dispatch_starved_waiting_for_serial_lane` at 240 s). Bypass `scripts/lib/git-api-publish.mjs`.
- "Modified vs local HEAD" is not contested: local HEAD lags remote main. Compare the worktree blob to REMOTE main (`GET /contents/<path>?ref=main`).
- `ci-status` ignores `rev`: an unpushed sha answers `unknown` + 422; query `gh api .../commits/<sha>/check-runs`.
- A red `npm run check` is usually FOREIGN (stale bake pins): read the failing line first. Re-bake `scripts/bake-heightfield.mjs --extent 256 --res 1 --sector 16 --bits 16`.
- `check-cache-keys.mjs` is shared: editing another transform's `BAKE_INPUTS_*` reddens `check` for every lane until the pin bumps in the SAME commit. Compute a pin from REMOTE committed blobs, reproducing the existing pin first.
- `scripts/check.mjs` parses TRACKED `src,client,apps,scripts,bin` only; `npm run check` runs the 139 steps of its `steps` array and does not discover the other witnesses, which are run by hand. A witness must exit 0 AND print `RESULT: PASS`.
- An absolute Windows path (`C:/dev/spoint/...`) in `scripts/*` is a CI-only ENOENT on ubuntu: resolve paths relative to the repo root.
- CI: completing jobs = `check` + `frame-time-coverage`; `frame-time` needs `vars.CI_GPU_RUNNER_ONLINE == 'true'` (else SKIPPED). Judge the newest CI-evaluated commit: `check-runs` on a `[skip ci]` bump is zero and reads as pass.
- CRLF: `core.autocrlf=true` only in SYSTEM config; `w/crlf` in `git ls-files --eol` = no diff.
- `.gitignore` ignores `runs/` (gm run logs) and `sources/` (fetched-source cache) as generated artifacts; neither has a tracked file. Its transient-runtime block ignores scratch logs and captures (`data/*.log`, `data/*.err`, `data/*.out`, `data/*.json`, `data/*.mjs`, `data/*.js`, `data/*.txt`, `data/*.png`, `data/*.glb`, `data/*.tmp.*`, `data/*/`, `.scratch_*`, `.smoke*.log`, `*.tmp`, and prof/, a gitignored output directory absent from the repo), while the gitignore negation !data/prefabs/ (for the `data/prefabs` directory) re-includes prefabs, so untracked scratch logs and captures are not committed. `data/placed-models.json` and `data/prefabs.json` are tracked despite matching `data/*.json`; the negation !data/prefabs/ re-includes `data/prefabs`, so `data/prefabs/demo-prefab.prefab.json` never matches the `data/*/` rule.
- `.gitignore` re-includes `.gm/*` only for the memories, `disciplines/project`, witness-log, witness-out and pool-log paths. `.gm/witness-log.md`, `.gm/witness-out/` evidence text and `.gm/pool/pool.log` are the tracked witness audit trail; `.gm/witness-out/**/*.wasm` binary plugin copies are ignored because they are not evidence text, and no WebAssembly file (`*.wasm`) is tracked or present under `.gm/witness-out/`.
- Untracking: `git_rm {cached:true}` + paths-scoped `git_commit {index_commit:true}`; `.git/index.lock` fails `git_commit`.
- Generated artifacts ship with source: `AppContext.js` -> `client/editor/sdk-typings.generated.d.ts` from the AppContext import closure; a pre-commit hook refuses a closure change without it. `scripts/gen-sdk-typings.mjs` generates it from `src/apps/AppContext.js`; inference is structural, parameter and return types are mostly `any`, and it is not a drop-in replacement for the hand-curated `client/editor/sdk-typings.d.ts` Monaco typings. Regenerate with `npm run gen-typings`; do not edit the generated file by hand.
- The generated file carries `export declare const SOURCE_DIGEST: '<64 hex>';` as a non-comment declaration. `scripts/lib/appcontext-closure.mjs` `DIGEST_LINE` and `recordedDigest` use that declaration, and `scripts/gen-sdk-typings.mjs --check` compares it with the current `src/apps/AppContext.js` import-closure digest.
- `scripts/gen-sdk-typings.mjs sortBlock` sorts declaration blocks by code point: tsc orders emitted members by type id, which follows module-resolution order, so sorting makes the emitted text a function of the member set rather than the checkout.
- gm MCP is HTTP on `127.0.0.1:8787/mcp`, never retries, so a startup gap detaches it (`/mcp` recovers).
- `@spoint/ecs` resolves only via `@spoint/*`; the link can vanish mid-session (`npm run links`).
- Never `git worktree remove` a `scripts/worktree-setup.mjs` worktree (its node_modules junction deletes `node_modules/.bin`); use `scripts/worktree-teardown.mjs`.
- `src/static/BakeCodeVersion.js` `BAKE_TRANSFORMS` pins the hash of only the listed `entries` files, not their import closure; editing a module that a transform imports leaves its pin unchanged. `src/shared/cacheCodeVersions.js` holds the `*_CODE_VERSION` constants that those pins hash into.
- `.github/workflows/ci.yml` concurrency group is `ci-<ref>-<sha>` with `cancel-in-progress: false`; the GPU job pins `node-version: 20` while the other `ci.yml` jobs pin 24.
- AGENTS.md is over the 30 KB target that 2fa8159 set; no gate enforces that target, so its size is recorded here as a note, not a failure.

## Validation

- Debug a failing path live before writing any test: reproduce it on the running dev server or with the one witness that names it, read the failure, then pin the fix with a witness.
- Iterate on `npm run dev` with HMR (see Dev HMR bodies), not on `npm run check`, which takes about 3 minutes.
- Run `npm run check` once per push, as the last step before the push.

## Stopping Processes

- Stop a process only by a PID you started or one a lease recorded: `browserPid` and `pid` in the lease owner record that `scripts/lib/browser-lease.mjs` writes. `browserPid` is recorded at spawn by `scripts/lib/cdp-browser.mjs` `launch`. Never run `pkill`, `killall` or `pkill -0`: a name or pattern match also stops other lanes' processes.
- A browser lease stops its recorded browser's process group (`killBrowser`, `scripts/lib/browser-lease.mjs`). On Windows, `reapProfileOwners` still finds chrome processes by profile path and stops those PIDs; the owner should review that sweep.

## PRD rows and witness binding

- A PRD row id is a claim until `prd_list {"id":...}` resolves it. Row ids collide across sibling sessions, so a `prd-add` can overwrite another lane's row.
- `prd_resolve` needs a `witness_dispatch_id` in THIS project's `.gm/pool/pool.log`, or all four of `witness_exit_code`, `witness_output_sha256`, `witness_output_path` (RELATIVE to the root), `witness_ts`.
- `.gm/prd.yml` has a concurrent-lane lost update: an `ok:true` `prd-add` can later answer "prd id not found". Re-add the id, then resolve. `git_finalize` is refused (`prd_foreign_rows`) while other sessions own rows.
- `prd.rs` reports `not_rerunnable` when a row's witness cites no existing `scripts/*.mjs|.js|.cjs`: a REPORT, not a regression.
- A truncated witness is a fabricated witness: never `.slice()` a log line you quote a number, flag or path from.

## Workspace links

- `scripts/ensure-workspace-links.mjs` never deletes a real install where a workspace link belongs. `ensureWorkspaceLink` renames a `real-directory` or `file` aside through `keepsakePath` (`.stale-copy` suffix), because that install is the only record of the bytes the dev server was serving. `rmSync` runs only on link kinds (`broken-link`, `link-elsewhere`).
- `assertWritesStayInTree` raises `WorkspaceLinkOutsideTreeError` before any write when a repair path does not resolve inside the tree being repaired. An archive whose node_modules is a junction onto another tree would otherwise rename and relink that tree's `@spoint` links, which live in the shared `C:/dev/spoint/node_modules`.
- `installPaths` must consider scoped specifiers: `packages/mapspinner` declares the unscoped name `mapspinner`, so a name-only check never inspects `node_modules/@spoint/mapspinner`, the real installed copy.
- `classifyInstall` asks whether a path resolves INTO `packages/<dir>`. A stale installed copy resolves perfectly, so resolution alone must not count as present.
- `ensureWorkspaceLinks` plans every link before writing any. One refused link stops the whole repair with nothing written.
## Witness and publish tooling

- `scripts/gpulock.mjs` `WAITERS_DIR` sits beside the lock dir (`${LOCK_DIR}-waiters`), because the lock dir's existence is the lock. `acquire()` takes the browser lease before the GPU lock and exits 145 (`EXIT_LEASE_UNAVAILABLE`) without claiming it, so a queued lane holds neither.
- `scripts/gpulock.mjs` `oldestLiveTicket`: lanes defer to the oldest live ticket. Tickets with a dead pid or older than `TICKET_MAX_AGE_MS` are removed, and a holder with no ticket is never waited on.
- `scripts/lib/cdp-browser.mjs` `launch` passes `opts.sinceMs` to the browser lease, so a caller that re-invokes `launch()` with the original `sinceMs` keeps its queue place. `scripts/launch-lease-since-witness.mjs` checks the ticket that `launch` writes, and `scripts/lease-queue-since-witness.mjs` checks the queue order. Nothing in the repo sets `SPOINT_GPU_LOCK_SINCE`, which gpulock reads.
- `scripts/lib/git-api-publish.mjs` `enforceCheckPinGate`: a publish touching `scripts/check.mjs` is refused when a pinned witness is in neither the commit nor the tip tree, and refused outright at zero parsed pins. It runs before any blob POST. The test itself is `missingCheckPins`, defined in `scripts/lib/check-pin-gate.mjs`.
- `scripts/lib/git-api-publish.mjs` `publishOnce`: each retry re-reads and re-hashes blobs and re-runs `planRebaseOnTip` against the new tip.
- `scripts/lib/tip-rebase.mjs` `planRebaseOnTip`: on a tip move, a path this publish left unchanged adopts the new tip's blob. A path both sides moved is refused as `REFUSAL_CONTESTED`.
- `scripts/lib/capture-server.mjs` `makeRootGuard`: a bundle whose hash differs from the boot pin answers 503 `root-hash-changed`. The hash memoises on mtime and size, so an unchanged bundle costs one stat per request.
- `scripts/static-export.mjs` `bundleAppsIntoSingleModules`: apps are bundled into single modules because `src/apps/AppLoader.js` evaluates app source through a Blob URL. That resolves relative imports against the origin root and misses the Pages base path.
- `scripts/planet-orbit-hitch-probe.mjs`: `ctrl.setMode('custom')` hands the camera to the probe. It is the only such call in scripts, src and client.
- `scripts/nearfield-lod-lattice-witness.mjs`: the transect window widens to `cl.extentM / 2`, so a ±30 m window cannot pass on the band alone.
- `src/terrain/GrassPlacement.js` `GRASS_FOOT_READS`: a blade's height at its clump offset reads the drawn mesh that many times, and falls back to the jet solve when a read is non-finite.
- `scripts/lib/js-token-stream.mjs` `tokenize`: the regex-vs-division choice follows the previous token (a `)` closing `if`, `while`, `for` or `with` opens a regex; a `}` always does). A misread hides a real comment from `scripts/comment-sweep-token-witness.mjs`, because the witness uses this same lexer on both sides. Treat a clean witness as evidence only when the swept files contain no `//` or `/*` outside template literals and strings.

- `scripts/lib/tree-under-test.mjs` `committedSource`: a clean checkout (`headIsWorktree`: no diff against HEAD in the work tree or the index) reads HEAD. Otherwise it reads remote main's tree (`publishedTree`, `GET git/ref/heads/main` then `git/trees?recursive=1`, cached under `.gm/tmp/published-tree`), because lanes publish through the GitHub Git API, which advances remote main without advancing local HEAD. A tracked path missing from that tree falls back to stage 0 of the index (`indexText`), so an unpublished file is read rather than dropped.
- `scripts/lib/tree-under-test.mjs` `worktreeStateRev`: `git stash create` writes objects only and touches neither the work tree, the index nor any ref, so it cannot disturb another lane's edit. The rev it prints is unreferenced, so a caller must use it in the same run. It returns null on a clean checkout, where HEAD already is the tracked state.
- `scripts/lib/tree-under-test.mjs` `catFileBatch`: all objects a scan needs come from one `git cat-file --batch` process. One process per tracked script was most of the audit wall time on Windows.
- `scripts/gpulock.mjs run <owner> -- <cmd>` holds the GPU lock as the directory `.gpu-lock` (`SPOINT_GPU_LOCK_DIR` overrides it), recording the holder in `.gpu-lock/owner.json`. `run` exits with the child's code, so the witness's own `RESULT:` line decides pass or fail.
- `scripts/lib/witness-audit.mjs --gate` compares per-file, per-check counts with the tracked `.witness-audit-baseline.json` and fails on an absent check id or a count above it. It is not wired into `scripts/check.mjs` or `package.json`, so run it by hand.
- Wireweave witnesses are manual only, by the owner's rule that only manual checks run, not automated ones: `scripts/wireweave-relay-roundtrip-witness.mjs` drives jayzee's `createWireweaveRelay` from `JAYZEE_ROOT` (default `../jayzee`, so it needs that sibling checkout) and `scripts/wireweave-send-contract-witness.mjs` and `scripts/wireweave-batch-refusal-witness.mjs` need no sibling. Run each with `node`. None is wired into `scripts/check.mjs`, `package.json` or CI. `WireweaveTransport.send` answers `SEND_ACCEPTED` once an item is accepted into the send queue, and the batch it joins is sent on the next tick. A refused batch surfaces later as a `send-refused` error event, not as the return value. Batching across sends is kept on purpose.
- `buildCrowdDots` (`src/netcode/SnapshotEncoder.js`) reports each crowd dot at its own cell, with the cell kept as a `[cx, cz]` pair rather than packed into one integer; a packed key decoded wrong for any cell whose x and z have opposite signs. `scripts/crowd-dot-cell-witness.mjs` pins this and is manual, not in the gate.
- The `Stage` radius queries (`getRelevantEntities`, `getNearbyEntities`, `getRelevantEntitiesHorizontal`, `getRelevantEntitiesForCell`, `relevanceRing`) take `radius ?? relevanceRadius`: an absent or null radius is the relevance ring, a zero radius is zero, and a NaN or negative radius is refused by the index. A `||` fallback turned 0 into the full ring. `scripts/stage-radius-zero-witness.mjs` pins this and is manual, not in the gate.
- `AppRuntime.nearbyEntities` and `relevantEntities` (`src/apps/AppRuntime.js`) answer the same radius query with or without a stage loader. Without one, `_radiusQueryWithoutStage` builds a throwaway `SpatialIndex` over the runtime's entities, so zero, positive, absent (the default relevance radius, since no stage supplies the world's) and NaN radii behave as on the loader path. Production always sets a loader (`src/sdk/server.js`, `src/sdk/WorkerEntry.js`), so only witnesses take this path. `scripts/app-runtime-no-loader-radius-witness.mjs` pins it and is manual, not in the gate.
- `scripts/world-port-distinct-witness.mjs` is manual and not in the gate. It imports the five shipped world definitions and fails when two declare the same `port` or the default world (`apps/world/index.js`, re-exporting `tps-game`) stops at 3002. The worlds take 3002 (`tps-game`), 3007 (`tutorial`), 3008 (`tutorial-rpg`), 3009 (`construct`) and 3010 (`deathrun`). Ports 3003 to 3006 belong to the `apps/world/_fixtures/sillos-terrain-*` fixtures, so the moved worlds skip them. A world's port applies only when it boots standalone (`WORLD=<name>`); a `?world=` query on the 3002 server does not change the port.
- `scripts/cross-map-parity.mjs` is manual and not in the gate. At jayzee `origin/main` fd92783 (its PARITY.md blob `dfb7815`) it exits 0 with `RESULT: PASS` and no PROBLEM lines. It reads jayzee's working-tree PARITY.md, so a dirty jayzee tree changes the result, and its PARITY check fails when that PARITY file has uncommitted edits (`git status --porcelain` on its directory, scoped to the file). Unrelated uncommitted spoint edits do not fail it.
- `scripts/perf-run.mjs` `avgMs` is a per-pass average and is INVALIDATED: it drain-biases low (25-36% in an earlier run, not re-derived at HEAD); quote `p50Ms` with `p95Ms` beside it, never the average.
## Client render placement

- The WebGL crowd dots (`makeDotMaterial` in `client/core/PlayerLOD.js`, used only when the renderer is not WebGPU, which is the `?legacygl=1` path) build the billboard basis as `right = toCam × up`, `camUp = right × toCam`, the same as `createDotMaterialTSL` in `client/core/PlayerLODTSL.js`. The earlier basis was mirrored, so the FrontSide quad wound away from the camera and drew zero pixels; the DoubleSide control drew them. Both twins apply the instance scale once, through the instance matrix: the shader used to multiply the offset by the instance scale too, which made the width grow as scale squared. `scripts/crowd-dot-render-witness.mjs` pins the visibility and the width and is manual, not in the gate.
- `client/core/Vegetation.js` `createVegetation` declares its tier-warm state above the species loop, because a `const` read from inside the loop body is in its temporal dead zone. On WebGPU, node graphs compile while species are built, so `warmTierMesh` warms each mesh once (`warmedTierMeshes`), and `createVegetation` does not resolve until `awaitTierNodeWarm` settles.
- `client/core/Vegetation.js` `prewarm`: each phase yields its own macrotask (`macrotaskYield`), because a millisecond budget checked between species cannot cut a species that is longer than a frame.
- `client/core/Vegetation.js` `createVegetation` species loop: a species failure is rethrown, never a shorter `meshes` list, since a partial list would look healthy.
- `client/core/ProgramReadiness.js` `pendingPipelineCount`: the common renderer has no `info.programs`. Readiness is read from the `renderer._pipelines` caches, where an entry stays pending until the backend assigns its `pipeline`. An entry with `error === true` is finished and is not counted.
- `client/core/ProgramReadiness.js` `installAsyncRenderPipelines`: an async creation that never yields a pipeline strands its object for good. The escort rescues after `ASYNC_PIPELINE_ESCORT_MS`, drains one rescue per frame, and clears `pipelineData.error`, because the WebGPU backend `draw` returns early on that latch.
- `client/core/ProgramReadiness.js` `installDeferredFirstUsePipelines`: `updateForRender` is wrapped here. An object not ready when a render bundle is encoded is built immediately, since bundles are encoded once and would otherwise omit it for good.
- `client/core/ProgramReadiness.js` `asyncPipelineState`: `requested` increments inside the wrapped `getForRender` each time an async pipeline promise is created. `scripts/program-readiness-render-witness.mjs` gates on it, because pending counts are timing-dependent: the first `render()` requests nothing, and requests arrive a frame later.
- `client/core/TerrainBackdrop.js` `createTerrainBackdrop`: the near-field lattice takes its spacing and extent from the collider (`cl.spacingM`, `cl.extentM`), so the mirror's density is the collider's, not a level count. The mesh mirror reads the baked lattice only when `cfg.bakedHeightfield` loads; otherwise each consumer keeps solving the sampler (`latticeRhoAlongDir` returns NaN and `surfaceAlongDir` falls back to the CPU solve).
- `client/core/TreeTextureBudget.js` `halvingsFor`: the texture budget can only be applied by halving decoded images at species build, because ez-tree builds its texture objects at module scope before client code runs. `client/core/VegetationBuild.js` `halveTreeMaterialTextures` is the only application.
- `client/core/TreeTextureBudget.js` `parseTreeTextureMaxPx`: an absent value falls back to the default, but a supplied invalid value throws `TreeTextureBudgetError` and is never coerced.
- `client/core/WebGPULodInstancer.js` `setLeafDrawDistance`: a non-finite or non-positive value means no cutoff (`on = Number.isFinite(m) && m > 0`). That is a silent default, so it is a known exception to the parse-at-one-boundary rule.
- `client/core/WebGPULodInstancer.js` `cellCrossesBand`: a cell straddling the leaf gate is classed `MODE_MIXED`, so per-instance gating runs; `MODE_UNIFORM` only when the cell does not cross the band.
- `client/core/CullFreeze.js` `setBatchedMeshCullAuto`: freezing a BatchedMesh sets `perObjectFrustumCulled=false` and must also set `_visibilityChanged`, because three's `onBeforeRender` reuses the standing list only when neither flag is set.
- `client/core/SceneOcclusion.js` `createOcclusionTier`: WebGPU renderers get `WebGpuHizTier`. The WebGL2 query tier's `supported()` returns `isWebGL2`, which is false on WebGPU, so its `runQueries` returns early.
- `client/core/SceneOcclusion.js` `createSceneOcclusion`: `queriedThisFrame` sums `entityTested` and `queried`, because the HiZ tier writes entity dispatch counts to `entityTested` and the other pass writes to `queried`.
- `client/core/ShadowCostProbe.js` `installShadowCostProbe`: the probe wraps a renderer-level `shadowMap.render` when present, else wraps `renderer.render` matched by shadow-camera identity, because WebGPU's `shadowMap` has no `render` and `ShadowNode.renderShadow` calls `renderer.render(scene, shadow.camera)`.
- `client/core/ShadowCostProbe.js` `_attachPerLightPass`: the per-light arm sets `splitSupported: false`, so `arm()` refuses the static/dynamic split there.
- `client/core/VegetationAmbientTSL.js` `updateVegetationTerrainAmbient`: the uniforms refresh per frame only on the WebGPU path, from `window.__timeOfDay`.
- `packages/streaming-gltf/src/cluster-lod-mesh.js` `_render` (the ClusterLodMesh._render method) runs once per group per frame through `onBeforeRender`, so keep its `_lastRenderFrame === frame` early return.
- A TSL `select` outside `uniformFlow` compiles to a real if/else branch (`node_modules/three/src/nodes/math/ConditionalNode.js` `setup`), not a ternary, so only the taken side runs.
- `CullFreeze.js setInstancedCullAuto` (`client/core/CullFreeze.js`) sets `autoUpdate` on the parent mesh and on every `LODinfo` level, so freezing and unfreezing act on every LOD level of the vegetation `InstancedMesh2` meshes (`client/core/Vegetation.js`), not only the parent.
- `FloatingOrigin.js update()` (`client/core/FloatingOrigin.js`, `createFloatingOrigin`) rebases by `camera.position.set(0,0,0)` and translates the other scene children by `-delta`, skipping the camera. Never shift the camera by `-delta`; that is a second shift.
- Veg LOD: `WebGPULodInstancer` `updateLOD` re-evaluates only after the eye moves `LOD_REEVAL_MOVE_M` (0.5 m, squared as `LOD_REEVAL_MOVE_SQ`). A leaf instancer built with `opts.host` is a satellite of its branch, and its `updateLOD` returns at once (`client/core/WebGPULodInstancer.js`).
- Terrain `renderOrder` is `TERRAIN_DRAWS_AFTER_OPAQUE_OCCLUDERS` (10) and water is `WATER_DRAWS_BEFORE_OTHER_TRANSPARENTS` (-1), both in `packages/mapspinner/src/tsl/planet-tsl.js`. Drawing terrain after opaque occluders is near-neutral for early-Z, since no terrain TSL material calls `Discard`; the TSL package's only `Discard` is in `packages/mapspinner/src/tsl/water-tsl.js` `colorNode`, which drops water fragments above `LAND_ABOVE_SEA_DISCARD_M`. Do not expect a win by drawing terrain first.
- `packages/streaming-gltf/src/cluster-lod-mesh.js` `_render` of `ClusterLodMesh` keeps its `_lastRenderFrame===frame` early return, because the render hook runs once per group per frame. The HiZ compute cull in `packages/streaming-gltf/src/webgpu-hiz-shaders.js` must equal the CPU cull, since divergence silently culls the wrong cells.
- `app.js animate()` (`client/app.js`) returns at once while `window.__warmupInFlight` is set, so never park a wait that needs a frame inside warmup.
- `applyDiff(uiRoot, hudVdom)` in `client/AppModuleSystem.js` `renderAppUI` runs over the HUD container every frame, so DOM children that are not in `hudVdom` are removed; mount imperative overlays outside that container.
- `client/core/CullFreeze.js` `setInstancedCullAuto` sets `autoUpdate` on the parent mesh and on every LOD level, so a frozen cull must reach all levels.
- `client/core/SceneSetup.js` `probeAndCreateWebGPURenderer` with `forceWebGL=true` runs THREE.WebGPURenderer on its WebGL2 backend, where terrain, sky and water do not render yet (mapspinner's WebGPU twin needs renderer.backend.device, which that backend lacks). `client/app.js` uses that backend only when WebGPU init fails and then throws rather than falling back to legacy; `?legacygl=1` is the only route to the GLSL renderer.
- `client/core/ShadowPipeline.js forceUpdate` sets `light.shadow.needsUpdate` on every cascade, and `cascadeCount` clamps to 1 when `sun.castShadow === false`, since cascade 0 is then the sun itself, which never renders.
- Vegetation LOD in `client/core/WebGPULodInstancer.js` `updateLOD` re-evaluates only after the `lodEye` moves `LOD_REEVAL_MOVE_M` (0.5 m), so a LOD decision can lag the camera by up to that distance.
- A leaf `WebGPULodInstancer` built with `opts.host` is a satellite of its branch: its `updateLOD` returns immediately and it mirrors the host's LOD pair, tier, shadow and visibility. Construction throws if its LOD tier or threshold counts differ from the host's.
- `packages/streaming-gltf/src/model-pool.js` drains (the impostor bake loop `_impostorCellBudget`, the cluster build `_clusterBuildQueue`) run only while their per-frame budget is above zero, so a zero budget (for example `opts.impostorCellBudget: 0`) never drains the queue; the fps ladders keep at least one unit per frame.
## Repo boundaries
- Agent routes: `src/sdk/ServerBoot.js` refuses to boot when the bind (`SPOINT_HOST`, default `0.0.0.0`, as `src/sdk/ServerAPI.js` `start` does) is non-loopback and `SPOINT_AGENT_TOKEN` is unset (`agentBindRefusal` in `src/sdk/AgentAuthoringAPI.js`, code `agent-token-required-for-bind`). ## Debugging discipline

- A bug surviving a threshold change isn't fixed; a reported cause is a claim until instrumented. Fix at its own layer end-to-end: a second copy of the same check isn't a fix (`ShapeBuilder.js`).
- **Silent-no-op class**: codesearch the reader and the enable bit first. Cases: `?noveg`, `__vdrsScale` (needs `window.__vdrs===true`), `?legacygl=1`, `window.__fsCheap` (enable bit set by `packages/mapspinner/planet.html`, read into the `u.fsCheap` uniform at `packages/mapspinner/src/tsl/planet-tsl.js`), `perf-run.mjs inputReachedGame`, MICRO_JITTER. REFUTED: `--no-walk` is not a silent no-op (`const WALK = !has('no-walk')` in `perf-run.mjs` empties the movement legs, so that arm is an idle walk).
- `__vdrsScale` is read only when `window.__vdrs === true` (`packages/mapspinner/src/gl-render.js`); VDRS has no consumer in `packages/mapspinner/src/tsl`.
- **Silent-default class**: `Number.isFinite(x) && x > 0 ? x : literal` and `v ?? DEFAULT` turn invalid input into the default. Parse the whole record at ONE boundary and refuse there (`ColliderStreamer.js`, `src/stage/stageShapes.js`). `typeof v === 'number'` admits `1e999`.
- **Named sentinel for absence**: a failed ground solve makes `guardedGroundHeight(where, heightFn)` return `NO_GROUND_HEIGHT` (`src/terrain/PlanetFrame.js`; its value is `null`). Callers test it only with `isNoGroundHeight`, never with `=== 0`, `Number.isFinite` alone or arithmetic, and convert it to NaN before any consumer that expects a height. The same pattern is `MESH_SURFACE_NO_GROUND` with `isMeshSurfaceNoGround` (`src/terrain/TerrainMeshSurface.js`, also `null`). `guardedGroundHeight` takes TWO args; a third argument is ignored.
- **No-data is not no-crossing**: `client/core/RelocationSearch.js` treats a non-finite height as no data. `coast` takes a shoreline only between two finite samples and never bisects into a no-data sample, `hills` skips no-data samples, and each search result carries `noData` with its sample count. A search whose every sample is no-data throws `RelocationSearchNoDataError` (code `SEARCH_NO_DATA`), and a rejected search is never cached.
- `scripts/relocation-search-nodata-witness.mjs` pins the no-data semantics of the RelocationSearch module, and runs in the `npm run check` gate.
- **Refusals carry a code, not prose**: `createClusterAssigner`, `assertWorld`, `StageLoader` (`StageConfigError.reasonCode`), `TickHandlerAOI` (`position|noPosition|unknownEntity`).
- **A module-level "report once" latch leaks across in-page rebuilds** (`PlanetFrame.guardedGroundHeight`). Put the latch on the returned closure.
- **A witness that mints ids as strings never reaches the parse boundary.** Mint integers. A fixture that never stamps a sender fails every `handle()`: `senderOf` reads the symbol `stampSender` writes.
- **A bare CLI flag parses to the string `'true'`**, so `Number()` yields NaN and disables the knob it sets.
- A witness needing the server to act on a client message passes `--params=multiplayer` (`?singleplayer` sees `players:0`). One `expect()` per measurement: a harness returning uncompared `{expected, got}` passes either way.
- One `gl.getError()` code covers distinct bugs (1282 = feedback-loop, sampler-type-mismatch AND insufficient-buffer-size): read the driver's console string. Live GL: `window`/`document` only via `page.evaluate()`; pin file:line via `addInitScript`.
- A witness child that dies must surface its stderr (`scripts/lib/witness-server.mjs`).
- `scripts/perf-run.mjs --knob=<key>=<value>[,...]` (or `?knob=` in `--extra`) sets number and boolean render-controls keys by their registry `key` verbatim (for example `maxLevel`, not `__maxLevel`). The values are injected at document start, so they land before boot-time reads. Unknown keys, wrong-typed values and a missing `=` are rejected before the run, and one bad key fails the whole run.
- Foliage toggles: `?lightplanet` (`client/core/TerrainBackdrop.js`) stubs the planet. `?veg=none`, `?nograss` and `?norocks` (`client/app.js`, flags declared in `client/core/RenderControls.js` and installed by `installRenderControls()` in `client/app.js`) really skip their layer. `?noveg` is not read anywhere and silently does nothing; `window.__vegAllOff` hides foliage per frame (`client/core/Vegetation.js`).
- `scripts/perf-run.mjs` `--knob=<key>=<value>` (or `?knob=` in `--extra`) applies render knobs by registry `key` verbatim (`maxLevel`, not `__maxLevel`) through a setter trap on `window.__renderControls`, so a knob lands when the page assigns it, before boot-time reads. The script injected at document start applies each knob with `registry.set`.
- `window.__vegAllOff` hides the foliage branch, leaf and shared-impostor meshes in `client/core/Vegetation.js` while set; `window.__vegHideFar` hides a named list the same way, and there is no per-part app toggle.

## Fire

- Integer-only kernel `fireKernel.js`: decisions from `hash(seed,step,face,I,J)`; no float, `Math.random`, `Date.now`. Per-cell step = `burnCell`.
- The per-cell step is `fireKernel.js burnCell`, in `src/shared/fire/fireKernel.js`.
- Rain smothers, doesn't eat fuel: a suppressed cell still burns `burnRate`, pushes no heat, spots nothing. Intensity 0..1 -> roll byte 255 via `rainPerIntensity` (`fireSpec.js`).
- `ctx.navCostAt(x,z)` = 8 burning / 2 charred (`_fireNavByRuntime`); `canSee` smoke-gated at depth >= `smokeBlockDepth`. Wind = weather BASE + `hash(seed,step)` gust, clamped +-16/axis; `snapshot().wind` carries BASE only.
- Per-cell initial fuel isn't recomputable in the kernel: a per-tile array in `snapshot()`/`restore()` joins `TILE_ARRAYS` + VERSION bump.
- A tampered keyframe is rejected at DECODE. `G` = ignition step mod 256, not age; IGNITE_AREA kind 5. `fireKeyframe.js` raises `[fireKeyframe]`; `rewindTo` verifies against `counters`, never `delta`, which at a boundary rolls back the step BEFORE it.
- A fire record promising work with no sampler is refused at construction (`src/behaviours/fireTerrain.js`): `firebreaks.kinds` defaults `['road','river']` while `kindAt` is null; `firebreaks.water` defaults true while `heightAt`/`seaLevelAt` are null.

Absent weather, a non-finite intensity and a non-array wind also yield rain 0; `reading.kind` keeps them distinct (`no-weather`, `unreadable-weather`, `dry-other`). `src/behaviours/fireWeather.js` pins this.

## Terrain and colliders

- `solveSurfaceY` tolerance absolute `1e-4` (`SURFACE_SOLVE_TOLERANCE_M`, `PlanetFrame.js`), 64-eval cap, throws `SurfaceSolveError`; past 63.6 km it returns `-(R+anchorHeight)` with no throw.

- Placement hot path has no-allocation forms: `tangentFrameInto`, `radialSlopeInto`, `quatMulF32Into`, `tangentFrameQuatInto` (`PlacementChart.js`); rock/veg `classify` use module scratch. Never test reach in face units: `u` is a tan projection. A unit box test left 87 holes in the 0-360 m rock ring at focus 240; after the chart-metre fix: 0 holes in 0-400 m at focus 240, 0 in 392-712 m at focus 240 and 450. The near-quad cache (`DEFAULT_MAX_QUADS`) must hold the disc: 128 thrashed at focus 240 (warm reads 163 ms per 13k), 512 gives 20 ms.
- `terrain.glsl`'s `snoise3`/`vnoise2`/`seaHash`/`hpfSample` take the in-cell fraction as `P-floor(P)` from ONE `floor`. Server terrain collider = ONE fixed-anchor local tangent plane (`anchorDir` default [0,1,0]): can't represent directions past ~87 deg from anchor.
- `gl-render.js sampleGroundM` is fire-and-forget async, so each call returns the PREVIOUS call's height; non-rAF callers use `sampleGroundMSync`, which poisons the next async read.
- `VegPlacement.js`/`RockPlacement.js` read climate before `surfaceOfCell` only when `climateUsesLocalXZ !== true`. Veg density must gate on painted snow, else surviving grass weight roots trees. Slope caps differ between `VegPlacement` and `GrassPlacement` (`SLOPE_MAX` 0.6 vs 0.9).
- REFUTED: `PlacementChart.js radialSlopeAt`'s 2-tap forward difference (it flips gates only where the gradient crosses `SLOPE_MAX`). Skipping a three.js attribute upload is safe only because a buffer is seeded from the whole CPU array on creation.
- Every `discard` in the fragment stage of `packages/mapspinner/src/shaders/terrain.glsl` sits inside the `#ifdef _WATERPASS_` block: a discard anywhere disables early-Z depth write for all its draws, so a new discard outside that block costs early-Z for every draw that uses it.

- `src/shared/terrainConfig.js` `terrainCarvesOf` returns no carves when `terrainHashVersionOf` is `LEGACY_TERRAIN_HASH_VERSION`, so carves take effect only on the non-legacy height backend.

## Grass distance-density

- `GRASS_DENSITY` + `grassBladeEdgeM` (`src/terrain/GrassPlacement.js`) are the single source of the law: `client/core/Grass.js` selects on it and BOTH `GrassTSL.js` and `GrassMaterial.js` mirror it in the vertex stage. Editing one side alone desynchronises the fade from the instance set with no error.
- A blade's rank `q` is uniform on [0,1) and stable for the blade's life, so `q >= f(d)` removes exactly the fraction `f(d)` and which blades go is never re-chosen as the player moves.
- `f(d) = (FULL_R / d) ** P` makes the surviving population grow as R ** (2 - P) instead of R ** 2. Inside FULL_R the keep fraction and the fade are exactly 1.
- The fade is shader-side: the CPU re-decides only every `LOD_REVISIT_STEP_M` (4 m). The CPU holds each blade from `LEAD_M` before its edge (`LEAD_M` must exceed `LOD_REVISIT_STEP_M` or a blade pops), and the shader grows it over `FADE_M` metres.
- `wind.uGrassRing` carries `EDGE_CAP_M = ringRadius - EDGE_M` (where the outermost fade reaches zero), not the ring radius.
- Placement is chunk-granular and the law is not, so a bigger ring places about twice the blades it keeps; the retired frame-time witness measured `updateMsPerQuietFrame` 1.03 -> 1.71 ms. Judge a ring change on that number, not the instance count.

## Grass wind field

- `client/core/GrassWindField.js` evaluates the gust once per lattice cell (64 x 64 over 192 m, riding the camera) and both shader paths read it with one bilinear fetch. The gust is one function of world position and time, so two blades a metre apart move together; the turbulence is a ripple that travels downwind.
- Every cell must be rewritten at the frame's time. With `GRASS_WIND_FIELD_BANDS = 8` each frame refreshed 1/8 of the rows, so one frame sampled rows from up to eight different times and the wind at a fixed point jerked. `scripts/grass-wind-field-seam-witness.mjs` (in the `npm run check` gate as step `grass-wind-field-seam-witness`; run it alone with `node scripts/grass-wind-field-seam-witness.mjs`): jerk ratio 231 at 8 bands, 6.4 at 1 band (cap 20). The 1-band cost is per frame CPU: in Node the lattice update rises from 0.07 to 0.55 ms (+0.48 ms). The browser cost is not measured; judge it on the frame-time number, not on this Node figure.
- The lattice origin snaps to `GRASS_WIND_FIELD_SNAP_M` (24 m), bounded by the slack the extent leaves over the reach, so the lattice is not rebuilt every frame. `GRASS_WIND_FIELD_REACH_M` (77.6) and `GRASS_WIND_FIELD_DROP_MARGIN_M` (16) bracket the ring that `Grass.js` keeps before it drops a chunk.
- A recentre that moves by whole cells copies the rows it keeps (`scroll`) and writes only the exposed border. With one band, `bandWrite` rewrites every row in the same frame, so a scroll costs the exposed writes on top of a full rebuild.
- The amplitudes are the constants the shader carried before the join (`GRASS_SWAY_BASE/FLOW`, `GRASS_FLUTTER_*`); the join changes where they are evaluated, not how large they are.
- `client/core/GrassMaterial.js` vertex stage: the gust is one bilinear fetch of `uGrassWindField` per blade, so neighbouring blades move together. `gw` (`gv * gv * 0.45`, with `gv` the clamped `position.y`) is the only wind term that varies within a blade, so it is evaluated per vertex and cannot ride the per-cell field.
- The distance growth `gGrow` scales a card uniformly on all three axes, while the fade `gIn` scales only `transformed.y`, so a card loses height, not width, as it fades.
- The card face turns to the camera by blending its in-plane axis toward `gTarget = gPerp`, which is perpendicular to the camera direction, with weight `gFace`. The card's face is a quarter turn from that axis, so it points at the camera as `gFace` reaches 1.

## Hot swap

A module that calls `globalThis.__spointHmr?.acceptSelf?.(import.meta.url, swap)` accepts its own edits. A save reloads only that module, and `swap(next)` re-assigns each export to the freshly imported copy. Re-assigning is what makes the edit visible: an ESM import is a live binding, so importers already holding the old copy read the new code on their next call. Self-acceptance therefore costs one module fetch per save, not a page load. It re-points code only and does not rebuild state the page already built. Walking up to an ancestor acceptor cannot help, because a re-import is a new module instance that existing importers never read.

## Dev HMR bodies

- A `?hmr=` body is a pure function of the file's bytes, the version floor, and the active version of the module and each of its direct imports. `rewrite()` stamps an import only while that import's version is above the floor, so a validator must cover exactly those. A body is re-sent only when one of them moves. `Cache-Control: no-cache` forces a revalidate before every use, so a reload answers 304 and does not re-read or re-rewrite the source.
