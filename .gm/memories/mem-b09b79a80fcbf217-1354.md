project/terrain-heightfield-streamer-per-player-clusters: The Jolt terrain heightfield streamer (src/terrain/HeightfieldStreamer.js, was createTerrainStreamer in TerrainPhysics.js) used to centre ONE 256 m field on the MEAN of all player positions; witnessed in Node (real PhysicsWorld + setupTerrainStreaming, synthetic players 0 and 10 km apart): field rebuilt at (5000,0), downward rays under BOTH players missed. Now: a set of fields (cap maxFields=8), corners snapped to the sample-spacing lattice so overlapping fields share sample positions; a player is covered if Chebyshev distance to a field centre <= extent*rebuildAt (0.4); each 300 ms pass builds at most ONE field for the first uncovered cluster (bbox midpoint of uncovered players within coverRadius of the seed), then retires fields that own no player (player owns the nearest field within half extent). All mutations run through one serialized promise queue (pass + resculpt). physics.setTerrainBodyId = field owning the most players (tps-game findSpawnPoints excludes only that one). Trunk/rock ColliderStreamer rings were already per-player (clusterCenters, maxCenters 8). Node CPU fallback samples a 128^2 field in ~11 s (baked hf only covers 512 m); worker uses GPU patch.
