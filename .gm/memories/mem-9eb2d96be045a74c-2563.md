project/cluster-world-heap-budget-measured-2026-10-06: the Jolt wasm heap is a fixed 134217728 bytes (128 MiB) from jolt-physics@1.1.0 dist/jolt-physics.wasm-compat.js and never grows; JoltInterface.sGetTotalMemory() returns exactly that and sGetFreeMemory() starts at 133059752 (1157976 B resident before any world). Exceeding it raises Aborted(OOM) inside `new J.JoltInterface` (src/physics/World.js:60), which kills the whole process and every world it hosts -- it does not degrade. A cluster server world costs a CONSTANT 20238432 bytes (19.301 MiB) marginal at every N from 1 to 6 (20236288 B empty, +2144 B for a connected grounded player); the first world costs the same as the sixth, so average and marginal agree and the only one-time cost is the pre-world resident. Therefore 6 server worlds is the most that fits at all (11.09 MiB, 8.7%, left) and the 7th aborts. CLUSTER_HEAP_WORLD_CEILING is now DERIVED in src/shared/clusterConfig.js from JOLT_WASM_HEAP_BYTES, JOLT_WORLD_MARGINAL_BYTES and CLUSTER_HEAP_RESERVE_FRACTION = 0.1 and yields 5, one below the raw maximum on purpose: a PhysicsNetworkClient with collisionMirror:true allocates its own client-side JoltInterface in the SAME heap at 10755000 B (10.256 MiB), so 6 server worlds plus the 2 mirrors scripts/cluster-world-harness.mjs scenarioHosting co-locates measures 137.4 MiB and OOMs by 9.4 MiB (witnessed 2026-10-06), while 5 plus the same 2 mirrors measures 118.1 MiB and fits. This supersedes the old AGENTS.md prose: 'about 21 MiB' was ~9% high, and the hand-set 5 was right only by accident. Two measurement traps, both hit: (1) a server-capacity probe that connects clients MUST pass collisionMirror:false or it overstates the marginal by 53% (10.26 MiB per client); (2) measuring only empty worlds understates production content, though content is cheap -- static body 266 B, dynamic body 392 B, character 416 B, 65x65 heightfield 16 KB. The cost is ~98% RESERVATION not content: bytes ~= 10645288 + 33*mMaxBodies + 88*mMaxBodyPairs + 336*mMaxContactConstraints, validated within 0.03% at the defaults (10240/65536/10240 -> 20191712 B) and at MIRROR_JOLT_LIMITS (128/256/256 -> ~10758056 B). Split at the defaults: fixed floor 10.152 MiB, mMaxBodyPairs 5.500 MiB, mMaxContactConstraints 3.282 MiB, mMaxBodies 0.322 MiB. So the lever for worlds-per-process is joltLimits (src/sdk/server.js:37 passes none, so every world reserves the defaults) and never world content -- see PRD row cluster-world-jolt-limits-right-sized. A world per player stays unviable at the defaults either way.
