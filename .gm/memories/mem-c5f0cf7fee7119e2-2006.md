v1 (legacy hash) boot: the CPU height sampler must not feed anything a player can see.

WHY: on a ?legacygl=1 boot the walked ground is a GPU patch bake while frame.elevationAtDir was the CPU transpile of the same GLSL; they disagree by the measured v1 floor (1.397 m mean / 4.109 m max over 625 dirs spanning 256 m, real GPU 2026-10-06). Consumers: src/shared/MinimapBiome.js (minimap elevation -> biome colour: beach 8 m, land 0 m, snow 2200 m bands), src/shared/relocation.js (seed only), src/terrain/PlacementChart.js (CPU branch only, consistent by construction). App-facing ctx.terrainHeightAt was never affected: it reads physics.setTerrainHeightSource's heightFn, already GPU/baked-backed.

FIX (landed): minimap elevation converts the frame ground with elevationAtLocal(frame, x, h, z) instead of a dir round trip through elevationAtDir; both GPU-patch writers (src/terrain/TerrainPhysics.js:179 server, client/core/TerrainBackdrop.js:101 client) set frame.cpuHeightDivergentFromGround, after which frame.elevationAtDir console.errors once naming the replacement; a seed-only read uses frame.cpuElevationAtDir (quiet). There are TWO writers of frame.groundHeightLocal's GPU repoint -- set the flag at both or the guard never fires (witnessed: divergent=false with only the server one set).

WITNESS (ANGLE NVIDIA RTX 3060 D3D11, ?singleplayer&legacygl=1, 25 cells over 256 m, GPU truth settled): minimap elevation vs GPU ground 1.446 m mean / 2.907 m max before -> 0.024 / 0.100 after; elevationAtDir calls 41 -> 0 (the one remaining call is the deliberate injection); guard injection: elevationAtDir warns, cpuElevationAtDir does not. CPU-path identity (node, real sampler+frame): elevation unchanged to 1.5e-5 m mean at v1, 4.6e-9 at v2. elevationAtLocal(frame,x,y,z) is exactly |p|-radius, so it equals the localToDir+elevationAtDir round trip on a CPU frame -- a safe drop-in.
