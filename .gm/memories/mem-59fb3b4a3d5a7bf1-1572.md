project/perf-bundle-content-age-not-copy-age: CORRECTS and supersedes [[project/perf-witness-serves-stale-prebuilt-bundle]] -- prune that one. MEASURED 2026-10-02. A prebuilt bundle in dist/ can carry hour-old code while looking freshly built, because `cp` without `-p` resets mtime to copy time, so the bundle's mtime proves nothing about the code inside it. The weather witness is the case: the served bundle stamped built 15:37:43Z, which is 17:37:43 local (UTC+2) -- one second before the arm started, so the COPY was fresh and my first read of 'stale bundle by two hours' was wrong in its mechanism. The CONTENT was bundle v1e built 16:05, about 90 minutes before the arm, and before the exact-at-impact ground sampling existed, which is why it measured rain splash placement off the ground by absMedian 0.165 m and absMax 1.485 m against source that cannot produce that. Lesson: never trust a bundle's file timestamp, trust its content hash. The guard that works is snapshot with `cp -p` so the true build mtime survives, and have each arm write its own bundle.json carrying bundleSha, bundleBuiltUTC, snapAtLocal, head, newestSrcAtSnap and srcChangedDuringArm, printing REJECT-SOURCE-CHURN when source changes mid-arm -- an arm run while someone edits source must be visible, not merely trusted. The height-sampling A/B survived this check: v1e and v1g were each snapshotted in the second before their arm launched, 1 minute apart, neither predating the other's code, so that closure stands (with the honest caveat that both were built ~20 min before the arms ran).
