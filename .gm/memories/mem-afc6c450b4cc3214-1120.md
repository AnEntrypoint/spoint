project/streaming-gltf-measure-fps-bench-method: packages/streaming-gltf/examples/local-progressive/measure-fps.mjs (npm run measure) benches stress.html served by serve.mjs on PORT 5180. It defaults the bundled Chromium to --use-angle=d3d11 --use-gl=angle: headless SwiftShader costs ~50s of cold shader compile and single-digit FPS (measured world-ready 28-30s on ANGLE vs 47-52s on SwiftShader on Windows/AMD); ANGLE=swiftshader or CHANNEL=chrome override, and the JSON 'renderer' field shows which path ran. Use ?assets=local (ASSETS env): the cross-origin default host never reaches instanced/BatchedMesh steady state inside the warmup. Use 127.0.0.1, not localhost (page.goto stalls under CHANNEL=chrome). Warmup is adaptive: it waits for the entity target and deferred-queue inFlight==0 to be stable for 4 checks, then settles 1.5s. Close other GPU-heavy tabs. stress.js raises the LodUnloadManager budget (default 200MB, evicts above ~0.85x) with the byte budget, otherwise hundreds of distinct models get evicted right after spawning. BatchedMesh far tier measured 68-70 FPS median vs 63 at 500 distinct models.
