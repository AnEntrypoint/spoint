## Resolved mutable: webgpu-e2e-weather-init-createbuffer-not-function

Root cause confirmed via codesearch+Read, not the trivial-fix case: client/core/Weather.js createWeather() constructs 4x InstancedMesh2 (@three.ez/instanced-mesh). InstancedMesh2.initIndexAttribute() (node_modules/@three.ez/instanced-mesh/src/core/InstancedMesh2.js:298,304) does `const gl = this._renderer.getContext()` then `new GLInstancedBufferAttribute(gl,...)` which calls `gl.createBuffer()` (GLInstancedBufferAttribute.js:17). Under WebGPURenderer, renderer.getContext() -> backend.getContext() (node_modules/three/src/renderers/common/Renderer.js:1991) -> WebGPUBackend.js:419-421 returns `this.context`, a GPUCanvasContext -- which has no createBuffer (that method lives on GPUDevice, not GPUCanvasContext) -- exactly producing 't.createBuffer is not a function'. Also confirmed weather is NOT a trivial-buffer-swap fix: (a) InstancedMesh2 is already established WebGL-only (mem tsl-grass-instancedmesh2-webgl-only), and (b) all 4 WeatherMaterials.js materials (makeRainMaterial/makeSplashMaterial/makeSnowMaterial/makeFarSheetMaterial) are raw THREE.ShaderMaterial with GLSL strings, which WebGPURenderer cannot compile (needs NodeMaterial/TSL) -- so a real fix is a full instancing+material TSL port, filed as new mutable webgpu-weather-particle-system-needs-tsl-instancing-port (comparable scope to the completed tsl-grass-streaming-webgpu-port). Applied interim fix: client/core/Weather.js now branches `if (renderer.isWebGPURenderer) return createWebGPUUnsupportedWeather(cfg)` before touching InstancedMesh2, returning a real no-op API (update/dispose/setType/getType/setIntensity/getIntensity/getSnowAccumulationAt/getWetness all safe no-ops, window.__weather still set) instead of throwing mid-construction. Live-verified via gm browser verb against real Chromium WebGPU backend at http://localhost:8099/?singleplayer&world=tps-game&webgpu=1&weatherType=rain: zero '[weather] init failed' console errors, zero GL errors (gl.errorTotalCount:0), and in-page probe read window.__weather directly -- {hasWeather:true, weatherType:'rain', isWebGPU:true, imNull:'null-noop', activeCount:0} -- confirming the noop path is live and clean, not the crashing InstancedMesh2 path. Weather does NOT render/function under WebGPU (activeCount:0 by design); it fails to crash cleanly instead, pending the follow-up port mutable.
