project/tsl-instanced-positionnode-and-tint-outputnode-2026-09-29: Two WebGPU-renderer root causes. (1) three r185 NodeMaterial.setupPosition runs instancedMesh(object) (positionLocal = instanceMatrix*positionLocal, normalLocal likewise) BEFORE material.positionNode; a positionNode that multiplies by its own instanceMatrix storage node must read positionGeometry/normalGeometry, otherwise instances are transformed twice (grass tufts oversized and floating over sillos roof/sky, skinned VAT player garbled on the WebGL2 backend). Fixed in GrassTSL.js (positionGeometry, world normal varying from normalGeometry), PlayerVATTSL.js, WeatherMaterialsTSL.js splash. positionNodes that only add an offset to positionLocal and never re-multiply are correct (VegetationTSL, batched-far-tier-tsl, instanced-slot-cull-tsl); PlayerLODTSL and octahedral-impostor-display-tsl already used positionGeometry. (2) ModelPoolAdapter tintCompose -> applyUnderwaterTintNode/applyWetnessTintNode set material.outputNode = f(material.colorNode); outputNode replaces the whole lit result, so every model-pool material on WebGPU drew raw unlit albedo (too bright, sillos looked smeared, colorNode edits ignored). Fix: wrap the lit `output` node from three/tsl. Numbers (tps-game, __tpOverride [-14.94,-2.15,-10], tod 0.4, vs fresh legacy shot): WebGPU meanAbs 39.8 -> 32.7, >32px 41.3% -> 37.0%, top 40% meanAbs 54.6 -> 27.1, luma 113.6 -> 96.1 (legacy 104.2); counters grass 8855/veg 9050/rocks 842 equal in legacy and WebGPU.
