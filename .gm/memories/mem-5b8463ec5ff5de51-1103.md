project/mapspinner-hpf-tap-fetch-coords-never-branch: packages/mapspinner/src/shaders/terrain.glsl hpfSample() -- the uHpfInset branch may change ONLY the interpolation parameter t (uv*(sz-1) vs uv*sz-0.5), never the four fetch coordinates c0..c3, which must always be clamp((t0+0.5)/sz, 0.5/sz, 1-0.5/sz). Texel i's centre is (i+0.5)/sz under BOTH bake conventions, so the old inset branch's t0/(sz-1) resolved under linear filtering to t0*sz/(sz-1)-0.5 and blended neighbouring texels -- an off-centre tap that made GPU terrain disagree with the CPU mirror by 9.475m at the origin on tps-game (radius 63600, reliefScale 0.001). It is machine-dependent: the old code silently agreed whenever the driver fell back to NEAREST (no OES_texture_float_linear), which is why it survived review. The WGSL sibling (webgpu/terrain-composeheight-wgsl.js) reads hpfPool as a storage buffer with exact integer texel indexing and was always correct -- it needed no change. Verify via window.__terrain.frame.groundHeightLocal(0,0) == 0 within patch-grid tolerance (~1m at 1.94m spacing); that single number caught it.
