project/gate-guard-defaulting-a-missing-field-is-not-a-guard: a gate guard that reads a field with a `||` default passes exactly when the field is missing, which is the case it exists to catch. Two instances found 2026-10-06. (1) scripts/frame-time-gate.mjs read `baseline.rasterizer || 'software'`, so the shipped .frame-time-baseline.json -- which predates scripts/lib/gpu-probe.mjs and has no rasterizer at all -- compared as software instead of being refused; the class-mismatch guard was bypassed in precisely the legacy case. Refuse the absent/unknown case explicitly and enumerate the admissible values instead. (2) scripts/cold-load-gate.mjs returned a bare number while its caller destructured `{ ms }`, so `undefined > limit` was false and the gate printed `measured=undefined` and exited 0. Both are one class: an undefined value silently satisfying the comparison that was supposed to reject it. When auditing a gate, look for `|| ` on any field the guard is about, and for a return shape that does not match the caller's destructuring.
