project/tsl-default-renderer-and-hashversion2-flip-2026-10-02: WebGPURenderer is now the DEFAULT renderer (client/app.js no longer gates on ?webgpu=1); ?legacygl=1 opts out to the legacy WebGLRenderer, ?forcewebgl=1 keeps WebGPURenderer on its WebGL2 backend. If WebGPU is unavailable the code retries WebGPURenderer(forceWebGL=true) before ever falling back to the legacy renderer, so TSL stays the only shader path on WebGL2-only machines. DEFAULT_TERRAIN_HASH_VERSION is now 2 (src/shared/terrainConfig.js) and a new LEGACY_TERRAIN_HASH_VERSION = 1 carries the old meaning in every 'is this the legacy float hash' test: terrainCarvesOf and terrainBakeKey (carves are v2-only), TerrainPhysics gpuPatchCollider (the GLSL patch baker is v1-only, so v2 worlds use the exact-CPU collider), TerrainBackdrop isLegacyHash, TerrainPhysics.bakedHashVersionOf and MinimapBake.isMinimapStale (an artifact with no version stamp predates versioning = 1). client/core/TerrainBackdrop isTslTerrain is now simply isWebGPU, so a hashVersion 1 world also renders through TSL instead of the third WGSL path. app.js forces ?terrainhash=1 when the renderer ended up legacy, because the legacy GLSL planet can only draw hashVersion 1. minimapBaseName keeps 'the default version is untagged' (v2 bakes are now tps-game.1337.minimap.png, v1 gets .h1), so every existing v1 bake is stale-detectable and rebakes.
