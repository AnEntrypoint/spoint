project/grass-placement-painted-splat-weights: GrassPlacement.classify multiplies its acceptance by the painted grass layer weight from packages/mapspinner/src/splat-weights.js (createSplatWeights({hashVersion}) -> splatWeights(dir,h,slope,temp,humid) -> reused {grass,rock,sand,snow} object). splat-weights.js is an exact CPU mirror of surface-splat-tsl.js w4 (bandWarp from snoise3 at dir*1100 and dir*2580, dryHot, beach, sandRegion, slope rock, snow band, rock band, underwater remap, +1e-4 normalisation); snoise3 comes from compileSnoise3 in tsl/ops-jsgen.js so the hash follows frame.hashVersion (1 float, 2 integer). Edit surface-splat-tsl.js w4 and splat-weights.js together. Inputs: h = rho - frame.radius (metres above the sea sphere), slope = 1 - 1/sqrt(1+grad^2) (= 1 - n.up of the shader), temp/humidity from climateAt. Weights cached per hashVersion in a module Map. Imported as bare 'mapspinner/splat-weights' (package.json export + importmap entries in client/index.html and client/editor/thebird-host.html). Only client/core/Grass.js uses GrassPlacement (main thread, no server/worker copy), so placement parity is renderer parity: witnessed 2026-09-30 identical instance counts on legacy WebGL2 and TSL WebGPU (hills (-2750,-750) 0, spawn (-15,-10) 5126, lush (400,-300) 9339, coast 0); Node chunk counts hv1: hills 1089->0, spawn 1188->627, lush 1309->1309; deterministic across repeated runs. The white-grey ground at the tps-game hills is legitimate snow (h=159 m, snow band [120,180]; weights grass 0 / rock .19 / sand .20 / snow .61), not a lighting bug. VegPlacement (trees/bushes) does not yet read the painted weights and still places bushes on snow.
