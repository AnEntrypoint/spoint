Measuring frame time on this box has two confounds that each produce a plausible-looking wrong number, and the fix for the second one is a design change, not a retry. (1) CPU ATTRIBUTION: `LoadPercentage=100` while the per-process CPU-time deltas sum to only ~42.5% of 16 cores -- the missing ~57% is unattributed kernel/DPC from the separate `C:\dev\train` GPU job running on the same machine. Gating a perf arm on total CPU therefore never opens, and the arm silently stalls waiting for a gate that cannot pass. Gate on `ours==0` instead: count only Chrome processes running the spoint profile, which excludes both the `train` job and the desktop user's own Chrome by construction. Interleave V1/V0/V1/V0 so any drift in the background load hits both arms instead of landing on one. (2) REBUILD-PER-ARM: an arm that rebuilds its bundle at arm start measures whatever the working tree happened to be at that moment, so each sample sees different code and the comparison is meaningless -- and it fails invisibly, because a bundle built from ten mid-edit files boots to `hasClient:false, appKeys:[]` and looks like a harness bug rather than a churn artifact. Fix: build the V1 and V0 bundles ONCE, back to back, from one tree state, and have every arm copy the snapshot instead of rebuilding; `dirty` then cannot move between samples and the only difference between arms is the variable under test. Also `touch dist/src/sdk/WorkerEntry.js` per arm so the server takes the prebuilt worker every time rather than falling through to raw ESM on some arms and not others. Log `dirty=<n>` per arm anyway -- it is what caught this. (3) Two rig-level traps: the rig rewrites `gpu-probe.ps1` at startup, so a gate probe that shares that file dies with EBUSY on the second arm and then reports `OURS=?` forever -- give the gate its own probe file. And the panel is 144 Hz (measured refreshHz 143.78), so frame times must be read against a 6.94 ms vsync budget: a p95 of 8 ms is a dropped-frame story here in a way it would not be on a 60 Hz panel. State the refresh rate next to every reported percentile. (4) Report disagreement, not averages: a pair of samples that differ by more than the effect being claimed is a discarded arm, not a mean -- and running a fourth sample after seeing the first three is not independent.
