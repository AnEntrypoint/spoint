feedback-red-ci-is-a-finding-not-environment: a CI red that reproduces on every recent
commit is a defect in the check, not the environment. I saw `npm test` red on my own push
and on all six preceding commits, concluded "pre-existing and not mine", and moved on. It
was a real defect: src/static/BakeCodeVersion.js hashed raw file bytes, so with
core.autocrlf=true this box computed 53ae5783eac2 for apps/world/tps-game.hf while CI
computed 1e14bb7bd0db -- red on every push, green locally, and unfixable by re-baking
because a re-bake records the same CRLF digest the artifact already carried. Fixed by
hashing LF-normalized text (f88ebb286d). The tell I missed: a check that is green
locally and red in CI on files nobody edited is a line-ending or path-case difference,
not flake; and "it also fails on the commits before mine" proves the defect predates me,
not that it is not a defect. Read the failing step's actual output before classifying any
red -- `gh run view <id> --log-failed` costs seconds. Same rule as the page-witness
console-error gate: a message a run printed about itself is a finding until read, never
noise to write off.
