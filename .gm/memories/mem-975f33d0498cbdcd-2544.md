## Resolved mutable: tsl-underwater-wetness-wiring-contract

Contract (precondition on any future caller, e.g. tsl-pool-audit's material-pool.js/model-pool.js wiring): (1) call applyUnderwaterTintNode(material, seaUniform?, seaShiftUniform?) and/or applyWetnessTintNode(material, specSumNode?, wetnessUniform?) AFTER the material's other node assignments (colorNode/opacityNode) are set, since the helper reads material.outputNode||vec4(material.colorNode,material.opacityNode) as its base and OVERWRITES material.outputNode — calling it before colorNode is set bakes in a vec3(1,1,1) placeholder. (2) Chaining order is commutative for the shipped math: applyWetnessTintNode(material) after applyUnderwaterTintNode(material) (or vice versa) both read the CURRENT material.outputNode as their base, so calling both composes them correctly regardless of order, since each only multiplies/mixes .rgb and preserves .a. (3) material.needsUpdate=true is set by each helper already — caller does not need to set it again. (4) World-position math assumes this project's floating-origin convention where render-space IS effectively world-space for TSL's positionWorld/modelWorldMatrix builtins (AGENTS.md floating-origin-camera-set-not-translate) — the original GLSL's explicit spointSeaShift term is preserved as-is in seaShiftUniform for the sea-surface curvature calc specifically (not a general position correction), ported unchanged. (5) OPEN GAP, not silently dropped: applyWetnessTintNode's specular boost defaults to float(0.0) (no-op) until a caller wires wetSpecularContribution(normal,lightDir,lightColor,viewDir) into a custom TSL LightingModel.direct() override per active light and passes the accumulated sum as specSumNode — this is a genuine LightingModel-level integration (same risk class as tsl-csm/CascadeShadowSelect.js's flagged non-trivial light-loop port per docs/webgpu-shader-audit.md), out of scope for this row, and NOT yet filed as its own PRD row — whoever wires wetness into material-pool.js should prd-add a dedicated row for the specular-loop integration before considering wetness fully ported. (6) Neither helper has been live-verified under an actual ?webgpu=1 WebGPURenderer (no browser witness taken, consistent with docs/webgpu-shader-audit.md's own stated audit-only scope); math verified instead against three.js's real GLSL->TSL transpiler (three@0.185.1) and against three/tsl's actual export surface (exec_js dispatch_ids 1790056227668-500-32731d4c9b745cee, 1790056289883), not merely hand-derived.
