spoint veg LOD: branch and leaf instancers of one tree species still each keep their own uniform-grid index and each rerun the full rebuild walk, so the same cells are classified twice per frame. Vegetation.js (client/core/Vegetation.js) builds branch and leaf with identical level distances (0, D1, D2), identical hysteresis LOD_HYS and an identical shared bounding box/sphere (_treeBox/_treeSph), and loadChunk feeds the same bucket to both in the same order -- so the cell classification (state/mask/mode/tier) is provably shared-able. The safe form is a shared immutable index (CSR start/cursor/counts over slots, per-cell posMin/posMax/cenMin/cenMax/minR/maxR) rebuilt once per edit batch, with per-instancer order/cellOf/mode/tier/stamp/active kept separate; the blocker is that order/cellOf hold per-instancer ids, so sharing needs either a slot->id map or an id-alignment assertion between the pair. Opportunity measured after the pending-rebuild fix: rebuildRecords is ~76% of remaining instance visits in the real90 shape (12797.5 of 16311.3 visits/frame), so sharing it across the branch/leaf pair is roughly a further 30-40% cut of counted work.
