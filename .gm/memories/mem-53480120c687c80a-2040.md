project/boot-terrain-missing-and-sun-frozen-2026-09-30: (1) Terrain never built on slow loads: client/app.js onWorldDef sent loadingMachine WORLD_CONFIG (and later MODELS_DONE) BEFORE assigning _terrainCfg = wd.terrain; when every other loading event had already landed (slow/contended GPU, e.g. NVIDIA at 100% from another process), the machine went ready synchronously inside onWorldDef, _finishLoading saw _terrainCfg null, skipped _buildWorldScenery (marks boot:loading-ready and boot:scenery-built at the same instant, no terrain:start) and nothing ever retried. Fix: assign _terrainCfg before the first loadingMachine.send and, if loading already finished with no backdrop, start _buildWorldScenery from onWorldDef. Witness: NVIDIA WebGPU/WebGL2 now terrain:start at loading-ready. (2) Sun direction never followed time of day in either renderer: TimeOfDay compared against NaN sentinels with `>` so `changed` was always false, onDirectionChange never fired, so the shadow offset and TerrainBackdrop.setSunLocal stayed at the boot direction while TimeOfDay also wrote sun.position = dir*200 in absolute space (direction skewed away from the origin because ShadowPipeline moves the target with the player). Fix: NaN-safe comparison, TimeOfDay ownsSunPosition:false when a ShadowPipeline owns light placement, ShadowPipeline.setSunDirection redraws only when the direction moved more than texelWorld(0)/20 m (one shadow texel at a 20 m caster; ~1.1 redraws/s with a 600 s day, fps unchanged 55-58) and repositions non-shadow-casting cascades immediately. After: light direction == TimeOfDay dir, sky/terrain sun planet-frame elevation matches; coast sand at tod 0.4 legacy 207,195,145 vs TSL WebGL2 207,194,144 (earlier ~181 values were with the frozen ~20 deg boot sun). (3) Foliage _ensure* guards now keep the in-flight promise per system (_foliagePending) and drop results from before a reseed (_foliageGen). (4) hashVersion-1 TSL loads still run the legacy GL patch baker which took 25 s on contended NVIDIA and gates boot:terrain.
