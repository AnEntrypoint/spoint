Pinned AMD TSL-vs-legacy parity rig: the 'executed mapspinner bytes equal disk' gate in scripts/tsl-parity/analyze.mjs (lines 104-108) is a line-ending comparison, not a build-provenance check. It hashes packages/mapspinner/<rel> from the LIVE working tree with no normalization and compares against V8's Debugger.scriptParsed hash of what the page executed, which for a pinned window is a materialized git archive -- and git archive applies core.autocrlf=true, so it emits CRLF for every text file. git ls-files --eol packages/mapspinner showed exactly 4 of 95 files as w/lf (src/tsl/planet-tsl.js, terrain-material-tsl.js, geomorph-snap-tsl.js, surface-splat-tsl.js) and those were exactly the 4 the gate reported, with byte deltas equal to each file's line count. Dev HMR is not involved: SPOINT_HMR=0 with no '[hmr] dev hot module replacement on' line leaves the deltas unchanged. Fix on the serving side is to normalize the odd files to the convention a fresh checkout produces (CRLF here); git diff --numstat stays empty afterwards and git add stages nothing, so no committed content changes. The harness fix is to normalize both sides -- scripts/pinned-verify.mjs already does this via its normalize().
