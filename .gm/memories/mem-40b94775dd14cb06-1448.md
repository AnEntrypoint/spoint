project/height-sampling-fix-doubles-frame-rate-memo-cell-inert: the Weather.js particle-respawn fix roughly HALVES main-thread frame time during real movement, measured clean 2026-10-02 (ours=0 train=0, 120 s route walker, matched distance 673.5 vs 659.8 m): height sampling 44.24% -> 14.39% of the main thread (msH3i 19.19 -> 6.15, msSnoise3 13.70 -> 4.22, composeHeight 11.35 -> 4.02), frame p50 27.78 -> 13.97 ms, p95 48.65 -> 34.68 ms, frames 4720 -> 6753, fps 36 -> 71.6. Cause: Weather.js _respawnDroplet/_respawnFlake sampled frame.groundHeightLocal at a brand-new random position on every recycle, ~26k calls/s from 3000 rain plus 3000 snow in a 22 m box, which was 65% of all sampling; PlacementChart.surfaceAlongDir via VegPlacement/RockPlacement.classify is the remaining ~25%. Quote frame time, not fps -- 71.6 is suspiciously 144/2, so it may be a ceiling. REFUTED IN THE SAME RUN: raising the height memo cell from 1 m to 2 m with the cap lifted from 32768 to 131072 entries does NOT reduce sampling -- v1i-cell2 measured 14.76% against v1e2-ghfix-clean's 14.39%, i.e. no better and marginally worse, so the 'the 32768 cap evicts cells during a long walk' hypothesis is wrong and the change should not be shipped as an improvement. The contaminated pair for the same fix read 28.8 -> 36.1 fps and 37.75% -> 13.06% -- both arms inside a 13-minute full-GPU breach -- so contamination roughly halved the apparent gain; never quote those.
