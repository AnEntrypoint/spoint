project/tsl-parity-matching-criterion-fixed-before-frames-2026-10-05: criterion for the TSL-vs-legacy parity witnesses, written BEFORE any frame was captured so a result cannot be read as a pass after the fact. A region matches iff cross-renderer mean absolute delta per channel <= K x effectiveFloor, where effectiveFloor = max(same-renderer noise floor, 1.0) and the noise floor is the mean absolute delta between two consecutive frames of the SAME renderer at the same pose (wind on foliage, frame jitter). K = 3. QUANT_FLOOR = 1.0 is one 8-bit level, because the sky region has no foliage and its same-renderer floor can be ~0, which would make any ratio meaningless. Why K = 3 and how it is checked: no repeat-boot floor spread exists yet; the AMD and NVIDIA boots of the same renderer give the first repeat-boot pair, and if one renderer's floor differs by more than 3x between the two GPUs, K = 3 is not supported and the result is reported INDETERMINATE, not pass. Regions: sky = rows 0-30% / cols 10-90% at the sky pose (yaw 1.0, pitch 0.35); distant = rows 45-55% / cols 15-85% at the horizon pose (yaw 1.0, pitch -0.12); near = rows 70-85% / cols 15-85% at the horizon pose. Every region's ratio is reported and each region above K is named (aboveK), never averaged. Haze A/B: haze-off frames compared across renderers isolate the surface term; haze contribution (on minus off) compared across renderers isolates the inscatter. All parity boots run hashVersion 1 at ?at=-2750,-750 with tod 0.45, clear weather, hazeMul 0.4 -- the legacy planet can only draw v1, so a pass says the TSL path matches legacy on v1 terrain, not that the shipped v2 terrain looks right; one unpaired v2 WebGPU frame per GPU is taken as a look-check and labelled as such. Every boot records the adapter actually used as read from the page (__rendererInfo.glRenderer), plus session list and training-process count before boot.
