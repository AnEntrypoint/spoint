project/parity-window-serve-a-materialized-snapshot-2026-10-06: A TSL-vs-legacy parity window cannot be pinned by stopping the clock, because the static server serves its own cwd and reads the live working tree, so any commit by a concurrent lane changes what the next arm loads. Pin by materializing the archive: git archive the chosen sha into .gm/pinned/<short>, start the server with that directory as cwd, and verify served bytes against the snapshot before the first arm and after the last. Two leaks bite even then: node_modules entries that are junctions into the live tree (materialize every package the page importmap can reach instead, converting repo-internal symlink targets into junctions into the snapshot), and a build-artifact cache keyed by content alone. A window that skips the post-verify has no provenance at all. Repo HEAD is not usable as that provenance on a rig where several lanes commit to main mid-window: analyze.mjs prints HEAD DISAGREEMENT whenever the window-close stamp differs from the server-start stamp, which both arms share, so that line is two times, not two arms.
