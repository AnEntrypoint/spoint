scripts/.amd-fps-diag.mjs measured the AMD rdna-2 iGPU at the frame-time gate's static pose (tps-game, 5066-5207 vegetation instances, ~315k triangles, bundle sha ea7cbe150f99) on 2026-10-07. Three probes in ONE page session: 1280x720 -> 2.5 fps (p50 392.76ms, 23 samples per 6s); 64x64 viewport -> 16.7 fps (p50 59.97ms, 31 samples); back to 1280x720 -> 76.4 fps (p50 13.10ms, 58 samples). Same scene, same draw calls (2.10-2.17 draws/frame, verified against renderer.info.render.calls deltas), so neither resolution nor vegetation density explains the spread -- the page is bimodal with box load. Control: a blank page in the same browser with the same args ran 56.8 fps with 0 longtasks and 2% main-thread busy while the app page ran 2.5 fps, and document.visibilityState was visible with hidden=false, so rAF is NOT being throttled by occlusion or backgrounding. The commit timeline agrees: no commit touching client/, src/ or apps/world/tps-game.js landed between 45b67de9 (18:05:57) and ee2e3baa (18:42:33), yet a settle probe read 21.10ms/97-frames-per-2s at 18:30 and 388-417ms/7-10-frames-per-2s at 18:36-18:56 -- identical code and bundle, 45 fps vs 2.5 fps. Reproducible quiet-window measurements at 60s capture: static p50 22.96ms / orbit 22.98ms (2575/2574 samples) and static 22.55ms / orbit 24.08ms (2122/2121 samples). Vegetation is not draw-bound at this pose: __vegProfile reports impostorInstances 5061 of 5083 with sharedImpostorDrawCalls 1, meshInstances 46, meshTierInstances [12,10,24], vegDrawCalls 73. So a slow AMD capture is a shared-box signature, not an AMD capability limit: re-run it alone, and treat any settle probe under 40 frames per 2000ms as 'this box is busy', not 'AMD is slow'. The CPU spin fingerprint in scripts/lib/host-contention.mjs cannot see this (it reported clean x1.13 on a run whose frames were 58-75ms with 500-1000ms tails) because the contention is GPU-side.
