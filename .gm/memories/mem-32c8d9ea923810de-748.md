Releasing the shared GPU lock: the holder process created by `node C:\dev\train\tools\gpulock.mjs run <owner> node -e "..."` watches ONE exact flag filename (e.g. .gm/gpu-release6.flag), chosen when the holder is created. Writing any other flag (gpu-release.flag, gpu-release5.flag) silently does nothing and the lock stays held with a live heartbeat, so train-3f keeps waiting after being told the lane is free (cost it ~12 min on 2026-10-05). Always read the holder's command line to learn the flag name it polls, write exactly that file, then verify with `node C:\dev\train\tools\gpulock.mjs status` that it reports held:false and confirm the holder pid has exited. A lane agent reporting 'release flag written' is not evidence the lock is free.
