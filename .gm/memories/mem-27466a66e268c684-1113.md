`src/shared/terrainConfig.js` `DEFAULT_TERRAIN_HASH_VERSION = 2`, but every consumer of hashVersion is v1-only, so the default silently downgrades the engine: `src/terrain/TerrainPhysics.js:131` gates the GPU-patch collider on `hashVersion === LEGACY_TERRAIN_HASH_VERSION` (v2 -> gpuPatch null -> physics falls back to solveSurfaceY, 16 x sampler.heightAt per candidate, and the gridRes clamp to gpuPatch.spacing never applies); `client/core/TerrainBackdrop.js:81` gates placement height on isLegacyHash; `scripts/bake-heightfield.mjs` refuses any hashVersion !== 1 so a v2 heightfield can never be baked; `minimapBaseName` tags only the NON-default version, so with v2 default the tag is empty and existing `.h2` minimap artifacts never match and are never refreshed. v2 exists because carves only work on v2 (`terrainCarvesOf` returns [] for v1), so this is carves-vs-fast-collider, not an accident. Before flipping the default, check whether `createPatchBaker` can accept hashVersion/carves -- it is currently called with only {radius, reliefScale, seed}, which may be the real limitation rather than the gate.
