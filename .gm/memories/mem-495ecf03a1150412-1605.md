A regression gate that reads a metric which is never populated CANNOT FAIL. scripts/cold-load-gate.mjs had exactly this shape: measureRealColdLoadMs returned a bare coldLoadMs while main destructured { ms }, so ms was undefined, `undefined > limit` is false, and the +25% cold-load regression gate printed `measured=undefined` and exited 0 on every run -- it never compared anything. Found 2026-10-06 while threading assertGpu through the witness scripts; the return was corrected to `{ ms: coldLoadMs, gpu }`, after which it reports 50901 ms against a 54552 ms baseline. The general class to hunt in any gate: (1) undefined/NaN comparisons -- `undefined > x` and `NaN > x` are always false, as is a destructured field that does not exist on the returned object; (2) empty-collection passes -- a loop over zero items reporting "0 failures"; (3) unreachable failure branches -- a swallowing catch, an early return past the comparison, a threshold defaulting to Infinity; (4) baseline/self-comparison; (5) a metric whose writer stopped running, so the counter is permanently 0 and the gate reads clean; (6) exit-code laundering (`|| true`, discarded pipeline status). The proof that a gate is sound is INJECTION: feed it a bad baseline, a zeroed metric or a threshold of 0 and confirm it goes red. A gate that stays green when you break the thing it guards is a silent pass. Corollaries here: .frame-time-baseline.json carries no `rasterizer` field and predates scripts/lib/gpu-probe.mjs, so its provenance is unknown; and a witness that prints its rasterizer class without asserting it is still not a gate.
