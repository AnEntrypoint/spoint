project/veg-cull-freeze-per-frame-and-occlusion-key-namespaces (2026-09-29): client/core/CullFreeze.js holds the one still-camera cull-freeze rule for Vegetation/Rocks/Grass, driven every frame from foliage-lod-sync via each subsystem's updateVisibility(camera, pose, shadowStill). It compares the camera pose at the last real cull. Before this, the freeze was decided only inside update(), which the PlacementScheduler throttles to 25 Hz (MIN_TICK_GAP_MS 40), and it keyed on the player focus instead of the camera. Rocks also compared rotation frame to frame, so a slow pan never re-culled. Streaming mutations set _cullDirty. Vegetation exposes castShadows:true so a shadowMoved frame forces a live cull. @three.ez performFrustumCulling zeroes every LOD object's count, shadow levels included, so a shadow map rendered on a frozen frame has zero tree casters. Grass chunk frustum visibility now runs per frame too. Vegetation applyOcclusion now uses branch/leaf setVisibilityAt(id); InstancedMesh2 without createEntities hands addInstances one shared _tempInstance, so the stored entities all toggled one wrong tree. SceneOcclusion keys streak records per subsystem (index:key); vegetation, rocks and grass all use 32 m chunk keys cx,cz, and before this 461 of 1407 keys were shared across subsystems and mixed their verdicts.
