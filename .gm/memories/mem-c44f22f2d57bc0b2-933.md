window.__spoint._drive is Relocation.js's walk hook (client/core/Relocation.js drive()): it mutates the input object only while a walker from walkTo/go is active, so calling it directly with {forward:true} moves nothing and silently reports zero displacement. client/app.js calls window.__spoint._drive(input, cam) every input step with the real inputHandler.getInput() object, so wrapping it is the sanctioned way to OBSERVE accepted input (perf-run.mjs does this), while INJECTING movement needs a real KeyboardEvent('keydown',{code:'KeyW'}) dispatched on both window and document. Measured with that path on ?multiplayer: 767 input steps in 11.6 s, forward seen 12 ms after keydown, 23 ms to first 0.05 m of local movement, input step period 15.0 ms. Also: the spawn room is a walled box -- straight-line walking from spawn stops at exactly z=-10.14 (2.36 m), so sustained-movement measurements need open terrain or turn-and-walk.
