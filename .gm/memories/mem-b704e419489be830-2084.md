A perf arm can measure a bundle that is not the code on disk, and disk mtime will not tell you. scripts/perf-run.mjs and .scratch_weather_witness.mjs boot src/sdk/server.js, which serves the PREBUILT bundle from dist/client/app.js and logs it as '[server] serving PREBUILT BUNDLE ... (built <ISO>)' from ServerBoot.js using the file's mtime. That stamp is UTC; local box is UTC+2, so 15:37:43Z is 17:37:43 local -- an arm that started at 17:37:44 was NOT two hours stale, and reading the Z stamp as local time invents a stale-bundle bug that is not there. The real trap runs the other way: the queue snapshots with `cp .scratch_bundle_X.js dist/client/app.js`, and plain cp sets mtime to copy time, so a bundle built hours earlier looks seconds old. Fix: `cp -p` so the served stamp is the true build time. Content age is what matters and mtime cannot show it -- record the bundle sha per arm instead. On 2026-10-02 the weather witness reported splash error absMedian 0.165 m / absMax 1.485 m / 28557 of 81574 impacts over 0.25 m; that arm served .scratch_bundle_v1e.js (sha ae47ab1b3d839223, built 16:05), which predates the exact-at-impact sampling in client/core/Weather.js, so the number measured memo-only code, not current source. The height-sampling A/B (v1e2-ghfix-clean, v1g2-nofix-clean) is sound: each arm snapshotted its own bundle in the second before launch and the two bundles were built 16:05 and 16:06. Guard: per-arm sidecar data/perf-run/<label>.bundle.json with bundleSha, bundleBuiltUTC, snapAtLocal, head, newestSrcAtSnap, srcChangedDuringArm (data/perf-run/src-stamp.ps1, src-changed.ps1); non-zero churn prints REJECT-SOURCE-CHURN. Also: unquoted & in a shell --extra=at=200,0&legacygl=1 backgrounds the command and splits the line, so arms silently never run and report `--seconds=120: command not found` (127); quote it. And killing a witness node makes bash report exit=127 -- the script writes its JSON then never exits because the sdk server keeps ticking a world in-process, so a 127 in a gate log means 'I killed it after it finished', not 'it crashed'.
