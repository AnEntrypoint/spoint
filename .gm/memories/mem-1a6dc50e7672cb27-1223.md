project/dependency-reachability-traps: when judging an npm dependency unused in spoint, a zero-import grep is not enough: assemblyscript is used only as the `asc` binary in package.json build:sph scripts, typescript only via node_modules/typescript/bin/tsc paths in scripts/check-sdk-types.mjs and gen-sdk-typings.mjs, monaco-editor only as the /node_modules/monaco-editor/min/vs path in client/editor/EditPanelEditor.js, bvh.js and other browser deps only as importmap entries in client/index.html and client/editor/thebird-host.html, ws only as `from 'ws'` in src/sdk/ServerAPI.js and src/sharding/RegionRouter.js. Removing a dependency with a big transitive tree (@gltf-transform/cli dropped 263 lockfile packages) can orphan an undeclared transitive import elsewhere: packages/streaming-gltf/tools/validate-extension.mjs imports ajv that only arrived through @gltf-transform/cli, so after that removal ajv must be declared or the tool deleted. After `npm install --package-lock-only`, `npm ls` reports the removed packages as extraneous until the next real install; that is expected, not breakage. The .gm/instructions/update_docs.md mention of flatspace is generic gm prose (spoint has no site/ dir), not a spoint use.
