project/streaming-gltf-example-draw-call-batching-traps: examples/local-progressive/draw-call-batching.js (per-geometry InstancedBatch, superseded by the BatchedMesh far tier). Traps fixed there: (1) key batches by the resolved geometry uuid, not meshIndex:primIndex; that key collides across assets (every asset has 0:0) and collapsed 900+ models into ~12 batches drawing one asset. (2) enableDrawCallBatching must wrap pool.update() to flush each batch, because pool.update() only flushes pool._instancedSlots; otherwise batched matrices stay zero and the models vanish. (3) The float instance-matrix texture must use NearestFilter, because linear filtering needs OES_texture_float_linear and raised GL_INVALID_OPERATION 1282. (4) Always upload dirty instance ranges; the old 5%-of-capacity gate cleared the dirty set without uploading, which made ghost models pop. cluster-lod-test.html notes that three skips onBeforeRender for an object with an empty draw range, so a mesh driven from onBeforeRender needs a non-empty sentinel range or group.
