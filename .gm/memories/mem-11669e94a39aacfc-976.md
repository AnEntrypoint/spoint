scripts/page-boot-witness.mjs must be given --params=multiplayer for any witness that expects the server to act on a client message (TERRAIN_SCULPT, TERRAIN_PAINT_BIOME, world config, entity edits). With the default ?singleplayer the server runs inside the browser worker, and the node server the harness itself booted logs players:0 for the whole run, so the message reaches a server with no ctx._terrainStreamer and EditorHandlers.js:486 acks it ok:false no active terrain streamer. The witness then reads no change and looks like a product bug. window.__terrain, window.__app.engine and the client chart frame are all present under singleplayer, and window.__colliderProbe is only installed there, so neither the presence of the frame nor the absence of the server effect points at the harness. Confirmed 2026-10-06: the same sculpt require read sent:true with localY unchanged for 32.5 s under singleplayer and moved 0.12047 to 8.05213 within one stroke under multiplayer.
