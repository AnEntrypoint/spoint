## Resolved mutable: sec-sweep-inputhistoryhardcap

codesearch/read confirmed the only caller of setTickRate() in the client is the connection-handshake/world-config path (server-authoritative tick rate), never derived from any network message field an untrusted peer controls per-message. The floor guard (Math.max(INPUT_HISTORY_SOFT_CAP+1, ...)) already prevents a pathological tick rate from ever collapsing the hard cap below the soft cap, closing the one theoretical DoS-adjacent shape (a hostile tick-rate value shrinking the buffer to uselessness) even though that value isn't attacker-reachable today.
