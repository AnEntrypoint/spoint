project/mapspinner-webgl2-sync-never-signals-in-task: WebGL2 never updates a fence's status inside the JS task that issued it, so a clientWaitSync(fence,0,0) spin loop can never succeed and just burns its whole time limit. gl-render.js sampleGroundMSync and bakeTileReadback spun up to 250 ms, measured 254.6 ms per probe and 252.5 ms per tile. For a synchronous readback, getBufferSubData straight after readPixels into a PBO blocks until the data lands, with correct values, in about 1 ms. Keep fences only for the async next-task path (sampleGroundM). The _PROBE_/_HEIGHTBAKE_ programs run composeHeight alone. Their only active sampler is uSculptOverride on unit 11, bound on every draw; HPF reaches only the terrain VS as vClimate. They need defRadius set, otherwise sculpt lookups collapse to the centre texel.
