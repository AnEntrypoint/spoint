project/appcontext-disposed-refuses-late-registrations: AppRuntime._releaseAppContext (hot reload + detachApp) calls ctx._runDisposers(), which marks the AppContext _disposed, fires each pending ctx.onShutdown hook exactly once (the runtime hook is a fire-once wrapper: it fires at context disposal OR at runtime.runShutdownHooks, whichever comes first, never both; the cancel fn onShutdown returns removes it), clears onConfigChange listeners, then runs registered disposers. A disposed ctx refuses (console.warn, no-op) time.after/every, onShutdown, onConfigChange, onPlayerProximity, players.onPlayerContact, world.spawnChild and interactable; _registerDisposer on it runs the fn immediately; unwatch fns it returned become no-ops so they cannot delete the next generation's entity-keyed proximity/contact watch. Why: timers and watches are keyed by entity id, so an async setup still awaiting at release added timers that fired beside the new setup's, and a late proximity watch clobbered the new one; onShutdown hooks accumulated one per reload (shutdown ran N+1 copies). Witness harness: scratchpad hr/release.mjs + hr/edges.mjs (real AppRuntime+AppLoader, queueReload+_drainReloadQueue, detachApp).
