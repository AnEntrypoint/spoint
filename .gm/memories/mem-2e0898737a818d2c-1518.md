project/webgpurenderer-impostor-atlas-orientation-and-normals: measured with a bake->shared-atlas->display harness on WebGPURenderer (both WebGPU and forceWebGL backends, IoU of impostor vs mesh silhouettes over 16 views). (1) WebGPURenderer ignores renderer.setViewport/setScissor when rendering into a render target and every autoClear wipes the whole attachment; per-cell atlas bakes must set renderTarget.viewport/scissor/scissorTest, clear once, autoClear=false (octahedral-impostor-ez renderAtlasCells). Old path: only one view survived (IoU 0.15). (2) Viewport y is top-origin on both backends, and TSL texture() does NOT flip v for these render-target textures, so the atlas is placed with yTop = size - yOffset - cell and the display material samples with v flipped (atlasFlipY, set by VegImpostorTier.atlasSampledFlipped for any WebGPURenderer). copyTextureToTexture destination rows differ per backend: WebGPU backend needs dst y = mega - (row+1)*tile, the WebGL2 backend uses row*tile (tileCopyRowsTopDown). Result IoU 0.82-0.86 on both backends. (3) The capture material must use normalView as is (MeshBasicNodeMaterial already negates on back faces); multiplying by faceDirection again inverted double-sided leaf normals. (4) The baked normal is the bake camera's VIEW-space normal and legacy uses it directly as the display view normal; the TSL port had multiplied it by mat3(cameraViewMatrix) as if world space, which scattered lit brightness 0.31-2.38x of the mesh; using it directly gives 0.45-1.38x.
