project/perf-arm-contamination-discipline-per-arm-wall-clock: every measurement arm must report its wall-clock start and end plus the load present during it, because a contaminated window is only detectable by comparing clock times against it -- nothing in the numbers themselves says so. MEASURED 2026-10-02: a peer session reserved the GPU, then a subagent under it launched a 512-world WebGPU run at ~84k world-ticks/s outside the peer's own queue for 16:03:28-16:16:30, which was found only by that peer disclosing exact times and by our arms carrying clocks. Contamination is not uniformly fatal, and the distinction decides whether a result survives: when BOTH arms of an A/B sit inside the same steady load, within-run shares and matched-distance deltas still hold (height sampling 37.75% -> 13.06%, calls 2.19M -> 0.71M over matched 660 vs 666 m travelled) because the load is symmetric, but every ABSOLUTE is depressed and must not be quoted (fps 28.8 -> 36.1, p50 34.76 -> 27.73). So report the delta and separately mark the absolutes unusable, rather than discarding the whole arm or quoting it whole. A GPU reservation is not self-enforcing: verify it (watcher on the lock file and on browser processes) instead of trusting it, and treat another agent's self-reported CPU as an estimate needing its clock to corroborate. When a shared box has multiple writers, serialise by explicit release word -- an agent that fires on its own stale estimate of a window will land inside someone else's arm.
