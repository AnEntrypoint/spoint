Fresh-room host boot root cause and fix, 2026-11-05.

Before: a fresh room logged "Connection failed: {\"isTrusted\":true}" at client/app.js:3068 and window.__app.wireweave/voiceIndicator/chatHUD were absent. The rejecting value was a worker ErrorEvent, not an Error.

Diagnosis chain (playwriter browser, page 3507294FC40921EE43C62CE5599B145B in a private context, dev server pid 150056 on 127.0.0.1:3102):
1. client/BrowserServer.js:139 had "this._worker.onerror = reject", so app.js's catch received a trusted DOM Event with no message.
2. Wrapped onerror into an Error with reasonCode worker-load-error, filename and lineno. Live console then read: "Connection failed: Error: [browser-server] worker failed to load: unknown worker error".
3. Added src/sdk/WorkerBoot.js, which imports WorkerEntry.js inside try/catch and posts BOOT_ERROR with the real message. BrowserServer now boots through WorkerBoot.js and rejects with reasonCode worker-module-error.
4. Live console then read: "Connection failed: Error: [browser-server] worker module failed to load: Failed to resolve module specifier \"three\". Relative references must start with either \"/\", \"./\", or \"../\"".
5. Root cause: six src/animation/*.js files imported bare 'three'. They are in src/apps/AppContext.js's import closure, so WorkerEntry.js's module graph reached them. A module worker has no import map; the page's index.html import map does not apply inside it.
6. Changed those six imports to the same URL the import map names: /node_modules/three/build/three.module.js.
