Deep-detail tier for AGENTS.md "Physics and Jolt" and "Terrain and colliders". AGENTS.md keeps the rule, the path and the symbol; this memo keeps the measurements and the reasoning behind them.

Jolt motion type and recreation
- `physics.setBodyMotionType` returns the NEW body id or `false`, never the old. In jolt-physics 1.1.0 wasm-compat a body created Static cannot be made to simulate by `SetMotionType`: `IsActive()` stays false and y holds 20.000000 over 60 ticks at gravity -18, while a control dynamic body falls to 11.005661. Hence the recreation fallback.
- `IsActive()` is the only discriminator — `GetMotionProperties()` is non-null even on a static-created body.
- Recreation must CREATE the new body BEFORE destroying the old (destroy-first frees a cached shape the new still points at, aborting the wasm with `null function or function signature mismatch`), must put it on `LAYER_DYNAMIC`, and must refuse a body holding a constraint, a vehicle chassis, or a trimesh/mesh/heightfield shape.

Body pool
- `AppPhysics.scaledShapeKey()` encodes model|scale only, so a static placed model and dynamic debris share a slot: a slot whose `bodyMeta.type` differs from the requested motionType must be destroyed and replaced.
- A matching slot is revived via `_revivePooledBody`: reposition, zero linear+angular velocity, `ScaleToMass` + friction/restitution/gravityFactor/damping/motionQuality, refresh `bodyMeta`. Forced destroy evicts the id from the pool.
- `removeBody` on a shapeKey-pooled DYNAMIC body must `DeactivateBody` and zero linear+angular velocity; pool revive must activate and zero both.

Other physics numbers
- `StaticTileIndex.update` stores the 16-value bounds record in a `Float64Array` and compares the integer tile span: 3.3879 -> 0.7946 us/call. It tiles static non-sensor bodies at 16 m XZ (+3 m margin); `|y|<10000` skips pool bodies parked at y=-100000.
- `BodyInterface.GetPosition` returns ONE shared temp, so two calls alias: `addConstraint` must read default anchors via `getBodyPosition`, or the distance constraint gets min=max=0.
- Heightfield samples snap to 1 mm with a deliberate `+ 0`: `Math.round` of a sample in (-0.5 mm, 0) yields -0, and -0 and +0 differ as `Float32Array` bits.
- Jolt wasm heap is fixed at 134217728 B and never grows; over it `new J.JoltInterface` raises `Aborted(OOM)` (`src/physics/World.js:60`). The three limits are not the same cap: `maxContactConstraints` under requirement drops contacts silently, `maxBodies` under population makes Jolt return body id 0 so overflow bodies share one map key and `destroy()` aborts the wasm.
- Jolt recycles removed bodies' tree nodes only in `physics.step`, so re-adding thousands of bodies with no step between aborts the wasm; static migration costs ~22 us per flip.

Terrain numbers
- `solveSurfaceY` is absolute `1e-4` (`SURFACE_SOLVE_TOLERANCE_M`, `PlanetFrame.js:3`) with a 64-eval cap and throws `SurfaceSolveError`; past 63.6 km it returns `-(R+anchorHeight)` = -63682.687 with NO throw.
- Two height backends; `gpu-eval.mjs` exposes `__sampleHeights(dirs)`. Over 25 samples across 256 m: v2 mean 0.001 / max 0.005 m, v1 mean 1.288 / max 2.840 m. Carves (`terrain.carves [{center,radius,falloff}]`, `terrainConfig.js terrainCarvesOf`) are v2-only; v2 also replaced GPU cos/sin with f32 `OCTAVE_ROTATION_COS/SIN` tables.
- `PlanetFrame.groundHeightLocal` memoises in 4096 direct-mapped slots keyed by EXACT `(x,z)` + chartEpoch (caching `SurfaceSolveError` too): 64 stationary players cost 22 us/tick vs ~10.8 ms, bit-identical to the uncached frame.
- A heightfield's sample grid covers a half-open cell span, so neighbouring patches disagree along their shared edge by up to a quantization step (seam max 0.014895 m). The bake's row-major sweep seeds each solve from the previous cell (3.1247 -> 2.2310 samples per cell); a cell that fails to solve resets the guess to NaN.
- GPU bake vs JS `composeHeight` agree only to ~1e-5 relative: float32 GPU-internal directions diverge through `value_ridged_fbm_rot`'s 18-octave w-feedback.
- `MinimapBiome.js sampleMinimapCell` returns `elevationAtLocal(frame,x,h,z)`, chart-independent to <0.0004 m; the old `frame.groundHeightLocal` differed by anchor height + `sphereDropBelowTangent`.
- `VegPlacement.js`/`RockPlacement.js` read the climate before `surfaceOfCell` only when `climateUsesLocalXZ !== true`, because sea-level XZ and surface XZ diverge by ~h*sin(theta) (~30 m at 20 km). Veg density must gate on painted snow: the 1-2% of grass weight surviving a snow cell still rooted trees in 12 of 193 placements across 120 tps-game chunks.
- The server terrain collider lives in ONE fixed-anchor local tangent plane (`createPlanetFrame`, `anchorDir` default [0,1,0], never re-anchored), so it cannot represent directions beyond ~87 deg from the anchor.
