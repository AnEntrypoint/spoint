Deep-detail tier for AGENTS.md "Rendering". AGENTS.md keeps the rule, the symbol and the path; this memo keeps the measured deltas and witness outputs.

TSL/WebGPU vs legacy GL
- `WebGPURenderer` is DEFAULT (`?legacygl=1` opts out); unavailable WebGPU retries it with `forceWebGL=true` before legacy, so TSL is the only shader path.
- WebGPU consumes TerrainBackdrop's `fE` DIRECTLY as the per-vertex clip transform (`patch-grid-render.js` WGSL `out.pos = frame.viewProjNoEye * vec4(vRel,1.0)`); WebGL uses `fE` only for CPU frustum culling.
- Legacy mixes the raw interpolated vertex normal (`terrain.glsl:781`) while TSL normalized it first (`terrain-material-tsl.js:163`); default `reliefShade` 6 amplifies 0.53 / 0.73 into the 3.11 / 5.67 left-edge delta.
- `three.webgpu.js` (pinned 0.185.1) calls `device.popErrorScope().then(fn)` with no rejection handler at 3 sites; destroying the GPUDevice with a scope pending rejects into an unhandled `OperationError: Instance dropped in popErrorScope`. `scripts/patch-deps.mjs` patches all three — three is served from node_modules, so no `dist/client/app.js` rebuild is needed. `MapspinnerPipelineCache.getPipeline()` must error-scope `createRenderPipeline`.
- `terrain.glsl` is the single source of truth for CPU/GPU height parity (`gen-height.mjs` transpiles it into height-gen.js/height-cpu.js); deleting it needs a new source of truth plus a TSL/WGSL->JS generator. Every discard in its FS must stay inside `#ifdef _WATERPASS_` because `gl-render` compiles the source twice and a discard anywhere disables early-Z depth write for all its draws.
- Depth contract: mapspinner re-encodes terrain/water depth to `window.__hostNearFar` (`passPlanetDepthWriteback`; WebGPU `DepthWriteback`).

Colour, sea, shadows
- `display-referred-tsl.js invertAcesFilmic` must NOT end in `max(x, 0)`: saturated blue (56,176,236) inverts to (-0.034,0.346,1.395) — negative red is out of AP1/ACES gamut — and clamping makes the re-encode 82.7 vs 55.9.
- Rendered sea = sphere R (== `PlanetFrame.waterlineLocalY`, exact to 1 cm) + waves that must be ZERO-MEAN about it: the old VS `swellP=dot(dir0,tangent-from-dir0)*R` heaved the ocean -0.40..+0.40 m (mean +0.254).
- `ShadowPipeline.js forceUpdate` must set EVERY cascade `light.shadow.needsUpdate` (three gates per light); `cascadeCount` clamps to 1 when `sun.castShadow===false`, and cascade 0 IS the sun and never renders.
- `QualityPresets.js` ships `ssao:false`/`bloom:false` on every preset because SSAO's half-res upsample leaves a dark ground-level smear; knobs stay live via `?debugpanel=1`.

Instancing, culling, geometry
- `patch-grid-render.js _ensureInstanceBuffer` must NOT reference-equality-guard a reused array: `collectQuads()` reuses one `quadsPool` every frame and that guard froze WebGPU terrain at frame 1.
- `ClusterLodMesh._render` fires once PER GROUP per frame; keeping the `_lastRenderFrame===frame` early-return prevents a mid-frame cull/LOD re-run rewriting start/count of queued draws.
- `webgpu-hiz-shaders.js` compute cull must stay algebraically equal to the CPU paths (HZB level = `hzb-tier.js _selectLevel`, occlusion = `isOccludedBox` with `minZ >= texel + 1e-5`).
- Vegetation LOD classifies whole cells on a uniform grid: `MAX_CELLS` bounds the loop by doubling cell size until it fits, `GRID_MIN_OCCUPANCY` keeps the flat scan for sparse instancers — the real world declines the grid.

Vegetation witness outputs (both real GPUs)
- `scripts/veg-instance-browser-witness.mjs --gpu=amd|nvidia [--walk=ms --route=...]` (`SPOINT_GPU_WITNESS=amd,nvidia npm test` runs both) passes on both real GPUs: vegTotal ~5000 settled, grass 7964, `streamState` missing=0 stale=0, no page errors. It must walk the player until instancers report instances before measuring — settling at first paint reads an empty world. The witness page serves `dist/client/app.js`, so run `npm run build:client` first.
- `client/core/PlacementRing.js keysAround` must return `PlacementLattice.ringAroundDir`'s numeric chunk keys UNCHANGED (`90c2bcad`) and throw on a non-numeric entry. Taking `r.key` over numbers made every distance NaN, so the ring passed the `> ringRadiusSq` load filter and failed `<= dropRadiusSq`: chunks loaded empty and unloaded forever, silently. AMD tps-game boot before/after: veg 0 -> 5072, grass 0 -> 7964, rocks 0 -> 114 (1862 chunks loaded, 73 draw calls, missing 0). Witness any ring change on BOTH GPUs asserting `vegTotal > 0`, `vegDraws > 0`, `grassTotal > 0`.
- Vegetation `InstancedMesh2`: `sortObjects` must stay false with LODs; `CullFreeze.js setInstancedCullAuto` sets `autoUpdate` on the parent AND every LOD level (3.7 ms/frame otherwise).
